# Android parity 2 — design

Status: design for the `feat/android-parity2` program (Levi, 2026-11-23: "add in the remaining features to bring
Android up to parity with iOS as the platform allows, and submit a new release").
Baseline: `main` @ `4bcd08db` (Android 1.0.0 live on Google Play, built 2026-11-05; iOS 1.0.6).
Inputs: the five area audits in `android/specs/parity2/audits/` (playback, pockets, vinyl-library, remote-social,
surfaces) and the iOS commits since 2026-10-26.
Plan: `android/specs/parity2/roadmap.json`. It has 86 packages in 12 waves and is generated by
`android/specs/parity2/tools/build_roadmap.py` from `tools/spec.py` and `tools/meta.py`. Each package's `notes` field
names the section of this document it implements.

Paths: `A/` = `android/app/src/main/java/com/levi/pocketdj/`, iOS = `apple/PocketDJ/`.

## 1. Principles

### 1.1 Port behaviour, not structure
iOS is the reference for behaviour. Each section lists the iOS invariants a port must keep: timing constants, guards
and the review-round fixes. Every one of these was learned from a real bug. The Android *structure* follows the
Android code that already exists:
- **One audio owner.** `SessionSwitchboard` owns the one MediaSession. Its owners are ExoPlayer via
  `SequencerForwardingPlayer`, the NP DSP via `NowPlayingDspSessionPlayer`, the Mix tab and Apple Music.
- **One queue.** The app-scoped `SetlistSequencer` is the queue. ExoPlayer holds only a 1–2 row window (D11).
- **One door for actions.** `ShellActions` is the door for every action triggered from outside the UI.

### 1.2 Data compatibility rule (D7)
Persisted and synced documents keep iOS key names and shapes byte-for-byte. New fields are additive and optional,
and the schema version is never bumped. Some documents are written by both platforms: `playback-session`,
`play-history`, `edits`, `pocket-palette` and `apple-music-library`. Android must not drop keys it doesn't know when it
re-writes them. Its decoders capture unknown keys (a `JsonObject` passthrough) and re-emit them.

The Android build that is live today violates this rule for `playback-session` and `play-history`. P2-DATA-1 and
P2-POC-1 therefore land in wave 1.

### 1.3 Release safety (D8)
A release can be cut after any wave (see `roadmap.release_cuts`: RC-1 after wave 5, RC-2 after wave 9, full after
wave 11). Some UI lands before its engine. That UI is hidden behind a constant in `A/ParityFlags.kt`, which P2-PB-2
creates. The engine package flips the flag:

| Flag | Added by | Flipped by |
|---|---|---|
| `DJ_MODE` | P2-DJ-6 | P2-DJ-8 |
| `POCKET_WHEEL` | P2-POC-9 | P2-POC-10 |
| `REMOTE` | P2-REM-7 | P2-REM-9 |
| `MIX_TOGETHER` | P2-REM-13 | P2-REM-13 |

Engine-only packages, such as the pure planners, analysers and transport code, have no user-visible surface. They
are safe to ship dark.

### 1.4 How the waves are built (D9)
`build_roadmap.py` places packages greedily, in priority order (P0 > P1 > P2 > P3), into the earliest wave that
meets all four rules:
1. The wave comes after the waves of all the package's dependencies.
2. The wave has 7 or fewer packages so far.
3. The package owns no file that another package in the wave also owns.
4. Every code file that is not a registration file is touched (owned or shared) by at most 2 packages in the wave.

Registration files are the DI graphs, the manifest, gradle files, `DebugScreen`, `SettingsSections`, `ShellNavigation`,
the deep-link tables, `shortcuts.xml`, `NPLog` and `ParityFlags`. Any number of packages may share them, but they get
additive edits only, and the integrator resolves the merges.

`check_roadmap.py` re-verifies every rule. To move a package, edit `spec.py` and rebuild; never hand-edit the JSON.

### 1.5 Logging
New NPLog lanes:
- `npmix` (Mix Mode lane and hand-offs)
- `dj` (transitions, declines, re-plans, leveling)
- `stall` (stall episodes)
- `pocketrun`
- `remote`
- `storage` (temporary sweep)

Each lane mirrors to logcat as `PocketDJ.<lane>`. Emulator steps grep these, so the line grammar is part of each
package's acceptance.

## 2. Sequencer extension seams (P2-PB-2, P2-PB-3) and the durable snapshot (P2-DATA-1)

`SetlistSequencer.kt` (1,641 lines) is the funnel for every start. At least ten parity-2 features need to observe it
or change it. Without seams, each feature would rewrite the same file in a serial chain, and each rewrite would risk
the generation, start-window and dead-air discipline that the parity-1 and answers programs paid for. So the program
starts by opening explicit extension points. After that, feature packages keep their logic in new files
(`playback/npmix/*`, `playback/dj/*`, `playback/album/*`, `remote/*`, `data/pockets/wheel/*`) and touch the sequencer
only additively.

### 2.1 Hook bus (`SequencerHooks.kt`)
```
interface SequencerListener {
  fun onSessionStarted(sessionId: String, source: SourceRef) {}
  fun onSessionEnded(reason: EndReason) {}                   // stop / replaced / finished
  fun onTrackStarted(start: TrackStart) {}                   // item, index, gen, path (EXO|DSP|AM|GROWING|ALBUM_GLIDE|DJ), fresh
  fun onTransition(t: Transition) {}                         // fromUid, toUid, cause: TransitionCause, seq
  fun onUserTransport(kind: UserTransport) {}                // play/pause/skip/prev/seek/jump/edit
  fun onQueueChanged(generation: Long) {}
  fun onRowLandedNext(uid: String) {}                        // P2-PB-3
  fun onFirstAudio(item: QueueItem, source: String) {}
  fun onHeld() {}; fun onResumedFromHold() {}
}
```
- Listeners are called on Main, in registration order.
- A throwing listener is caught and logged, and playback continues.
- `TransitionCause` takes the iOS set: `USER, NATURAL_END, AUTO_SKIP, STALL_HOP, UNPLAYABLE, REMOTE`. The existing
  `AdvanceCause.AUTO` is split into `NATURAL_END` (a real end) and `AUTO_SKIP`/`STALL_HOP` (a dead source, a stall).
- `transitionSeq` and `lastUserTransitionSeq` support the Remote local-change diff.
- `queueGeneration` bumps on every mutation of the queue.

### 2.2 Interceptors and advance-without-load
- **`StartInterceptor`.** Before the default resolve/load in `playCurrent`, registered interceptors are asked in
  priority order:
  - album glide continuation: 100
  - DJ incoming already in the DSP: 90
  - growing-file start: 50
  - FX/Stem lock engage at start: 10, which runs after the load as an `onTrackStarted` step instead

  The first interceptor that returns `Claimed` owns the start. It calls `completeClaimedStart(gen, path)`, which
  runs the same bookkeeping a normal start runs:
  - generation claim
  - start window and runway
  - watchdog arm
  - history/stats event
  - skip-tracker arm
  - `DeadAirMeter.transitionBegan`

- **`AdvanceInterceptor`.** On a natural end, interceptors may take the advance. Album glide does
  `seekInFile`+retarget; DJ advances at fade start. `advanceWithoutLoad(cause)` is a normal advance minus
  `PlayerPort.load`. It covers:
  - index move
  - repeat counter
  - `noteAdvanceAway`
  - ONE history play
  - meter
  - hooks
  - persist
  - re-plan

  Both the DJ conductor and album runs use it, so their bookkeeping cannot drift apart.

### 2.3 Queue APIs (P2-PB-3)
- **Row fields.** `QueueItem` gains:
  - `plan: PlanTag?` with `{runId, slot, collectionId?, score, pinned}`, excluded from equality as on iOS;
  - `pinned`;
  - `djUserNext`.

  `moveUpcoming`, `moveUpcomingNext`, `moveUpcomingToEnd` and the inserts mark a row pinned. That is the listener's
  claim on the row. `onRowLandedNext` fires for every edit that lands a row at `index+1`. DJ uses it to set the pick.
- **`replaceUpcoming(replacements, removing)`.** Pocket runs use it. Protection is checked again when the change is
  applied, because the queue may have moved since the plan was made:
  - never at or before `index`;
  - never a row with no plan, or a pinned row;
  - `index+1` only with at least 30 s of runway;
  - a row with a pending rip only for an on-device or instant replacement.

  A replacement takes the old uid's `canonicalOrder` slot, so unshuffle stays correct. When `index+1..+3` is touched,
  `NextRowPreloader` is re-armed. `appendRunRows` is edition-stamped like `play()`.
- **Effective repeat.** `repeatForcedOff` is a provider; pocket runs bind it. `effectiveRepeatMode` feeds the
  MediaSession, widget and Auto. `setRepeatMode` does nothing while repeat is forced off, and the sticky mode is
  never written.
- **External-driver APIs.** These are generic, and Remote is the first user:
  - `applyingExternal{}`: transitions are tagged REMOTE, ▶/⏸ inside it is not listener intent, and the gate is
    bypassed.
  - `play(items, startIndex, atMs, startPaused)`.
  - `jumpToUpcoming(uid, atMs)`: the start cue travels WITH the jump. A seek after the jump would land on the old
    backend.
  - `insertUpcoming(items, beforeUid)`.
  - `silenceForController()`.
  - `noteListenerPlayIntent()`.
  - `transportGate: ((TransportRedirect) -> Boolean)?`.

### 2.4 Durable snapshot (P2-DATA-1)
`SessionSnapshot` gains typed optional DTOs:
- `npMixMode{enabled}`;
- `fxLock{enabled, effects{raw:{on,strength}}}`;
- `djMode{enabled, planner}`, where `planner` stays a raw `JsonObject` until P2-DJ-10 decodes it, so the UInt64 seed
  survives untouched;
- `Row.plan`, `appleMusicId`, `djUserNext` and the legacy `djPlaced` (read-only: it maps to the pick only on the row
  after current).

Unknown top-level keys and unknown row keys are passed through. Encoding uses `explicitNulls=false`, so a doc without
these fields re-encodes byte-identically to today.

`SessionExtras` (P2-PB-2) is the runtime side:
- A feature registers its key with `write()` and `restoreHeld()`.
- A restore delivers the value HELD: Mix Mode, DJ and FX are restored, but nothing is armed, planned, analysed or
  buffered before the first ▶.
- An index-move write persists `positionMs 0`.

## 3. Playback correctness fixes (P2-PB-1)

### 3.1 FR1: a cancelled Apple Music start must never sound
**Failure, Android today:**
1. `PlaybackController.loadAppleMusic` wraps `backend.play` in `runCatching`. That swallows the
   `CancellationException` from a stall hop or a skip.
2. It then resets `activeBackend` to the prior backend. MusicKit already has `prepare(playWhenReady=true)` in flight.
3. The hop target's `stopAppleMusic()` does nothing, because `activeBackend` is no longer `APPLE_MUSIC`.
4. When the SDK reaches PLAYING, `AppleMusicPlayerAdapter` claims the session and pauses ExoPlayer.

**Fix:**
- `loadAppleMusic` rethrows cancellation.
- In a `NonCancellable` block it stops the SDK (`stopNow`), clears `current` and `playConfirm`, and restores
  `activeBackend`.
- `AppleMusicBackend.play` stops the controller in `finally` when it was cancelled after prepare.
- This matches iOS `supersedePendingPlay`: a superseded start never sounds and never claims the session. The Exo
  path is already fenced by `owns(gen)`.

### 3.2 Stall episodes (ping-pong)
Android counts a manifest hit as "instant", but those rows still stream. Two stalled rows can therefore hop back and
forth every 6 s.

The iOS rule (532ac59f):
- **Episode.** An episode is consecutive hops with no row reaching first audio.
- **Abandoned set.** `ResolveStallHop.choose` takes an `abandoned` set of uids, and the sequencer adds each stalled
  uid to it. On-device rows are still preferred, and multiple distinct hops are allowed.
- **Episode end.** The episode ends on any of these:
  - first audio (ExoPlayer AND Apple Music);
  - any user transport;
  - stop.

  It logs `stall episode end reason=… abandoned=N`.
- **No target.** With no eligible target, the current row keeps buffering, with no cancel/restart loop. The deferred
  stalled row is re-ordered to sit right behind the hop target; it is never dropped. With DJ on, it becomes the
  next-up pick (§6.5).

## 4. Now Playing Mix Mode

Mix Mode turns Now Playing into a one-deck mixer that can act on the *next* songs before they start, because it
buffers them. iOS built it in four phases. The Android port keeps the same order and splits it into packages by file
ownership.

### 4.1 Phase 1: temporary vs pinned assets (P2-MM-1, P2-MM-2, P2-MM-3)
**Ledger** (`BurnModels`, `BurnStore`, `TemporaryHolds.kt`):
- `TemporaryHold(songId, audio, stemParts, cutFile?, createdAtMs, expiresAtMs, userFolderPath?, userFolderFiles?)`
  is stored in `pocketdj-burns.json` as `temporaryHolds`. The field is additive-optional, per device and never
  synced.
- **No hold means pinned.** Media that already existed never becomes temporary.
- Writes are tagged with an `AssetOrigin` of `explicit(reason)` or `buffer`. A buffer landing writes a hold only for
  what it *created*.
- `pin(songIds, reason)` runs inside every explicit `BurnStore` entry point, BEFORE the freshness skip. That way an
  explicit download of an already-buffered song converts it. Studio explicit uses pin through the same funnel
  (P2-MM-3, reasons `demux`, `tracks-stems`, `sample`, `take`).
- `MixStreamLoader.open(origin)` defaults to `explicit("mix")`. When an explicit opener joins a buffer stream, the
  stream is upgraded (explicit wins).

**Sweep** (`TemporarySweep.kt`, called from `StorageManager`):
- `sweepTemporary(now, reason, capOverrideBytes?)`.
- It stamps `lastTemporarySweepAt` FIRST, so a crash can't cause a sweep storm.
- It does one ledger-only scan (no per-file disk walks on main).
- It deletes in chunks of 25 with `yield()` and re-reads the protected set per chunk. It is single-flight.

The **protected** set:
- the current row's base and resolve ids;
- the NP window (current + `npMixBufferAhead`);
- the held restored window;
- Mix decks;
- live streams and claimed stem sets;
- the Mix auto head.

An expired but protected hold is re-checked on the next sweep.

**Triggers:**
- launch, after the first frame;
- foreground;
- hourly while in the foreground;
- the existing `StoragePruneWorker`, not gated on the soft cap;
- Mix Mode off (cap only);
- the disk guard.

Soft-cap eviction removes unprotected holds first (soonest expiry), then the least-recently-played pinned burns.

**SAF picked folder.** At creation, record name → lastModified. Delete only files we created that are unchanged. A
folder switch releases. With `npMixKeepPickedFolderBuffers` on, a file is pinned at creation.

**Settings keys** (iOS-verbatim, `NpMixSettings.kt`):

| Key | Default | Notes |
|---|---|---|
| `npMixBufferTTLHours` | 48 | 0 = Keep. A corrupt or negative value reads as the default. |
| `npMixBufferCapGB` | 2 | |
| `npMixBufferAhead` | 3 | Options 1/3/5/10 |
| `npMixCellular` | `nextSong` | |
| `npMixModeDefaultOn` | false | |
| `npMixKeepPickedFolderBuffers` | false | |
| `lastTemporarySweepAt` | | |

A change to TTL or cap applies only to newly buffered assets.

### 4.2 Phase 2: toggle, lane and swap-on-land (P2-MM-4, P2-MM-5, P2-MM-6)
**`NowPlayingPrefetcher`** generalises the Stem Lock lane: there is one lane for everything.
- `plan(input)` is a pure function of:
  - `mixMode`;
  - `window`;
  - `isRipServerConfigured`;
  - the track sources: `local | ripped | appleMusicOnly | catalogOnly | live | studioOrProfile`.
- Order:
  1. rips (step 0, phase 4);
  2. the current `.song` if ripped but not local;
  3. the current stems;
  4. the next song;
  5. the next stems;
  6. rows 2…window;
  7. muted parts last.
- **With Mix Mode off the plan is byte-for-byte the Stem Lock plan.** A regression test over the existing cases pins
  this.
- Network classes come from `ConnectivityManager`: NOT_METERED = unmetered, metered = expensive, and Data Saver =
  constrained. The cellular policy is `off | nextSong | full`.
- `DiskGuard` runs before every step. It needs at least 1 GB free after the step and a temp footprint under the cap.
  Otherwise it calls the injected sweep, and if that doesn't free enough it skips with `UNAVAILABLE("Storage full")`.
  The sweep is bound to `StorageManager.sweepTemporary` in P2-MM-5, so the two packages could land in the same wave.
- The lane never cancels a pending explicit Download. The playing row waits up to 90 s.

**`NpMixCoordinator`** (`playback/npmix/`) is a `SequencerListener` plus the `SessionExtras` key `npMixMode`. It:
- reads `play()` from `npMixModeDefaultOn`;
- clears on `stop()`;
- restores HELD;
- is suspended while the Mix tab runs;
- never re-orders the queue;
- runs the lane worker, one step at a time;
- adds NP current + next to `MixStreamLoader.pinnedIds`.

**Swap-on-land (`SwapOnLand.kt`).** This runs when the playing row's `.song` lands while the row plays the presigned
ExoPlayer stream of the SAME rip. ExoPlayer is reloaded onto the local file at the same song-relative position, with
`playWhenReady=false` until the seek lands. A side→side or side→cut move is re-based on `startMs`. Under Stem Lock
with stems, the DSP is engaged directly instead. Its invariants:
- **A hand-off never starts audio.** It is refused when audio focus is lost or transient, when the listener paused,
  or when the engine no longer intends to play.
- If the local file fails, the row reverts ONCE to the presigned stream at the same position. A second failure
  advances.
- A `PlaybackRunway` wakelock is held across the reload until first audio (cap 10 s).
- The own-stamp match is URL + song, because two songs of one analog side share a file.
- When the Mix tab goes idle again, an owed hand-off is retried.

**UI (P2-MM-6).**
- **Panel header.** The header is always shown while a session runs; today it only shows when the row is local. It
  carries:
  - the Mix Mode switch (`np-mix-mode`);
  - the status chip (`np-mix-mode-status`), with the iOS words from `NpMixMode.Indicator`: OFF / READY / ENGAGED /
    BUFFERING(f) / HOLDING(f) / STEMS_LOADING / RIPPING / READY_FROM_AM / UNAVAILABLE / SUSPENDED /
    WAITING("Buffers on ▶");
  - buffer dots (`np-mix-buffer-strip`). A dot is full only when the file the row WILL play is local.
- **Menus.** The mini-bar and record long-press menus get the toggle.
- **Settings ▸ Playback.** It gets three rows: start in Mix Mode, buffer ahead, and cellular policy.

### 4.3 Phase 3: playing the growing file (P2-MM-7, P2-MM-8)
**`GrowingFileSchedule`** is pure. It is lifted out of `StreamDecks`, so the Mix decks and the NP DSP share one
schedule. It provides:
- `bytesPerSecond`, `playableFrames`, `frontier`;
- `canStart`, with a 2 s start runway and a 4 s resume runway;
- `shouldAppend`, `underrun`, `coveredFileSeconds`.

**`NowPlayingDspEngine.engageStreaming`** reuses the Mix deck's growing-Voice path:
- It never schedules past the frontier.
- A hold freezes the playhead and keeps the play intent.
- `NowPlayingDspSessionPlayer` reports BUFFERING while holding.
- **A headerless mp3 (no Xing/Info/VBRI) is never attached on a partial length estimate.** It is held unattached
  until complete (76dc87ed / b4d679e9).
- `MixStreamLoader` fans progress out to multiple listeners and marks cancelled or evicted streams `failed`, so no
  reader waits forever.

**`GrowingStart`** is a StartInterceptor. A row is eligible only when all of these hold:
- Mix Mode is buffering and the Mix tab is idle;
- the app is not in device mode;
- the row is ripped;
- the row is not Apple-Music-first;
- the row is not an analog song without a cut;
- the row was not refused this play;
- for a restore-resume, the resume point is no more than 15 s deep.

The fallbacks:
- **Touch hand-off.** When the listener touches a control while the row plays from ExoPlayer, and the touch position
  is covered by the buffer, playback moves onto the DSP.
- **Long hold.** A mid-song hold longer than 5 s leaves the DSP. The row goes back on its plain stream at the same
  position, with no truncation.
- **Route loss.** `ACTION_AUDIO_BECOMING_NOISY` pauses the DSP.
- **Supervisor.** The playback supervisor never acts while the DSP owns audio. The 5 s fallback is the DSP's own.

### 4.4 Phase 4: Apple Music rows (P2-MM-9)
`preferLocalAudio` is true while Mix Mode is buffering. It reorders the resolver ladder in `RowResolverRegistry`,
`AppleMusicRowResolver` and `CloudRowResolver`: a ripped AM row whose local copy is complete, or whose presign is
already cached, plays the rip, with AM behind it as the fallback. An instant AM start is never traded for a slow
presign (the dead-air rule).

AM audio is DRM'd inside the SDK on both platforms, so it can never go through the DSP. The equivalent is the **touch
hand-off** (`AppleMusicHandOff.kt`):
1. Read the AM position.
2. Engage the DSP on the local copy, paused.
3. Call `stopAppleMusic`.
4. Start the DSP and claim the session.

It happens only on the first control touch, never automatically (Levi Q1). It has a 3 s tail guard and records the
`DeadAirMeter` cause `npmix-am-handoff`.

**Rip-ahead.** The lane rips the next 2 AM-only rows through `PlaybackRipWindow`, fire-and-forget and never for the
playing row. iOS gates this on the catalog owner. Android has no owner identity, so it gates on "a rip server is
configured". That is Levi's own-rip-server rule; it is a needs_levi item with that default.

### 4.5 Stem Lock edition rule A (P2-MM-10)
Rule A applies when Stem Lock carries stems with **vocals muted** and a *preference* row's wanted edition has no rip
or burn. The row then plays the **base cut** plus stems:
- The base cut is resolved rip-first, never from AM.
- The substitution is sticky for the row, and un-muting keeps the substituted file.
- It never applies to `editionLocked` rows or Q94 clean-only skip rows.
- The buffer dots follow the substituted audio id.
- Log line: `[npmix] edition-substitute row=… played=… requested=… reason=vocals-muted`.

## 5. FX Lock (P2-FX-1)

FX Lock is the effects analogue of Stem Lock (`FxLock.kt`, iOS `FXLock.swift`). The state is
`FxLockState{enabled, effects{raw:{on,strength}}}`. The raw keys `compressor/reverb/flanger/filter` already equal
Android's `Effect` raw values. Unknown keys are kept on disk and ignored on apply. The state is stored in
`SessionExtras["fxLock"]`.

**Capture.** Only USER effect actions are captured. `NowPlayingDspEngine.onUserEffectChange` fires from the panel
only, never from carry, never from DJ automation and never on restore. Tempo, pitch and gain never carry.

**Apply** happens at track start, as the last step of the host's locks-on-track-start chain, the same place Stem Lock
applies:
- When the lock wants FX, the host engages the DSP on every mixable start path: burned/local, studio/profile, stem
  cut, growing file, swap-on-land and AM hand-off.
- `applyCarriedEffects` ramps ON effects up from transparent over 0.25 s. A user touch beats the ramp.
- A non-mixable row plays dry, and the indicator shows WAITING.
- While the Mix tab is live, the indicator shows DORMANT.
- `engage` refuses a file it can't open and leaves the track on ExoPlayer. iOS: "never playing over dead air".
- A lock engage of a complete playing file records exactly one dead-air transition.

While the lock carries effects, the lane fetches the next songs (no stems), so FX can apply at their start.

**UI.** A capsule sits in the Effects header, upper right (`np-mix-fx-lock`). There is no new row and no status line
(Levi 2026-11-03).

**Scope.** The lock lasts for the session: a new `play()` or `stop()` clears it. Skips, edits and restore keep it.

## 6. DJ Mode

DJ Mode makes Now Playing mix song into song automatically. It is built from:
- a shared transition math module (§6.2);
- a two-deck transition engine (§6.3);
- a conductor in the sequencer (§6.3);
- skip mix (§6.4);
- the PocketDJ selector (§6.5);
- loudness leveling (§6.6);
- progressive on-device analysis (§6.7);
- an automation display (§6.8).

### 6.1 Model, settings, session shell (P2-DJ-5, P2-DJ-6)
**`DjMode.kt`** holds `DJModeState{enabled, planner?}`, the settings, the timings and the Indicator words, all
verbatim from iOS. The settings are:
- `djTransitions`, `djEffectSweeps`, `djTempoMatch`, `djKeyMatch`, `djVolumeLeveling`, `djTempoWaves`, `djPockets`.
  Each defaults to true when the key is missing.
- `mixVolumeGlide`, which defaults to false when missing.

The toggles **mask** parts of DJ Mode off. They never change the shared Mix timings: lead 3–60, fade 1–12, skip
1–60, glide 1–30.

**Settings ▸ Mixing** (`MixingSettingsScreen`) has three groups: Crossfades, Now Playing DJ Mode, and Mix tab.

**`DjModeController`** (a SequencerListener plus `SessionExtras["djMode"]`):
- ON turns Mix Mode on, seeds the planner (`fxSeed` over the queue), requests a re-plan and engages the current local
  row.
- OFF disarms and levels to 0 dB. The track carries on.
- `setMixMode(false)` turns DJ off.
- `play()` and `stop()` clear it. A restore brings it back HELD.

`djActive` requires `enabled && Mix tab idle && no Remote session`. The Remote probe is an interface; P2-REM-5 binds
it. The suspended chip reads "DJ — paused · Remote session" or "DJ — paused · Mix tab".

The DJ chip sits LEFT of the Mix Mode chip (`np-dj-mode`). The DJ words ride the Mix Mode chip ("Mixing · DJ — next
mixes in"). The chip floor fills from 0 to 1 over the crossfade. The UI stays hidden until `ParityFlags.DJ_MODE`.

### 6.2 AutoTransition (P2-DJ-1)
`AutoTransition` is pure and shared by Mix Auto-DJ and DJ Mode. It provides:
- `advancePlan(secondsLeft, fade, glide, fxGlide, mixGlide)` and `immediatePlan`;
- `equalPowerGains`, `glideParams`, `outgoingRamp/incomingRamp`;
- `rollTexture`, `fxSeed`;
- `BeatRef`, `phaseAlignOffset`.

Its constants:

| Constant | Value |
|---|---|
| headroom | 1.12 |
| minRunwayFade | 0.5 |
| minImmediateFade | 0.2 |
| preRollMargin | 0.3 |
| rate | 0.5…2 |
| pitch | ±12 |
| texture run | 3–5 at strength 0.5–0.8 |

`splitmix64` is bit-identical to iOS. `GlideMachine` and `AutoDj` are refactored onto it without changing behaviour;
their existing tests are the guard. The iOS `AutoTransitionTests` vectors become goldens.

### 6.3 Two-deck engine and conductor (P2-DJ-7, P2-DJ-8)
**Engine design (D2): "ping-pong decks".** The Android NP DSP already runs a private two-deck `MixGraph`, using deck
A only with the crossfader pinned at 0. DJ uses **deck B for the incoming song** and the graph's equal-power
crossfader as the fade. When the fade completes, the live deck flips, and the listener's controls are re-pointed at
it. iOS needs a sample-accurate outgoing→tail move because its main chain is what the controls address. Android
avoids that by re-pointing. Each deck's `trimDb` carries leveling. Ramps are driven by an engine-side ticker of at
least 50 Hz that runs only during a transition; the 4 Hz host heartbeat is too coarse.

`DjTransitionEngine` (owned by `NowPlayingDspEngine`) runs this state machine:
```
IDLE ──armDj(lead)──▶ ARMED ──lead window reached──▶ PREROLL (incoming on idle deck, phase-aligned, glide ramps)
PREROLL ──fade start──▶ FADING (crossfader sweep; onFadeStart(songId) → sequencer advances)
FADING ──fade done──▶ POSTROLL (glide eases out, live deck flipped) ──▶ IDLE (onTransitionEnded)
any ──cutTransition(reason)──▶ HANDBACK (before advance & song still playing: hand back at playhead, glide eased 0.5 s)
                              └▶ IDLE (after advance: other deck stopped)
```
Transport rules:
- Pause pauses both decks.
- A seek cuts the other deck.
- Stop cuts everything.
- A listener touch in ANY phase ends the glide without a jump (the listener wins).

The engine refuses with a decline reason when:
- it is not playing, or is holding;
- the outgoing song is a growing file;
- a stem handover is in flight;
- the outgoing song has muted stems;
- the incoming file is unreadable;
- less than 0.3 s is left.

Any stop that fires completions bumps the generation at the commit point (`stems-toggle-generation-discipline`).

**Conductor** (`DjConductor`, `DjDecline`). At track start, as the last lock step, it decides using ONE decline list.
The same list feeds the decision, the fade-start re-check and the chip (`djEndReason`). The sequencer-side reasons
are:
- transitions are off;
- repeat-one, or a repeat count;
- a cascade halt;
- the last row (with repeat-all the reason is "set repeats");
- an album run is playing through;
- the next row starts an album run;
- the next row is not a complete local file.

The engine's own reasons from above are added to these.

The plan is `advancePlan(secondsLeft × min(1, 1.12/outRate), fade, glide, fxGlide: effectSweeps, mixGlide:
tempo||key)`:
- glide only with Tempo or Key match on;
- texture only with Effect sweeps on;
- incoming gain only with Volume leveling on.

**At fade start** the conductor calls `advanceWithoutLoad(NATURAL_END)` (§2.2). That performs:
- `DeadAirMeter` cause `dj`, with first audio at once;
- ONE history play;
- card metadata published from the DSP owner;
- Stem/FX Lock applied to the incoming song;
- re-arm and re-plan.

**`PlayerPort.adoptDsp(request)`** leaves ExoPlayer idle, and `NowPlayingDspSessionPlayer` owns the MediaSession
through the whole transition. There is one audio owner and one card writer.

**Failure paths never delay playback:**
- A refusal at fade start (the queue moved) puts the outgoing song back.
- An incoming song that fails to open after the advance plays the plain way.
- A DSP end advances tagged NATURAL_END, never AUTO_SKIP.

### 6.4 Skip mix (P2-DJ-9)
`skipNext(fast)` routes to `DjSkipMix` when DJ is active:
- **No transition:** `immediatePlan`. The fade is cut to the runway: at least 1 s, with 0.5 s to spare.
- **Pre-roll:** drop the pre-roll and fade now over the skip length.
- **Paused in pre-roll:** advance immediately.
- **Mid-fade:** ignored.
- **Post-roll:** end the glide and mix out of the new song.

A skip is a USER transport:
- It calls `noteUserTransport`, records meter cause `skip`, and the skip tracker records it at the PRESS.
- It overrides repeat-one and repeat counts, and lifts a cascade halt.
- The pending skip is keyed on the run's incoming song. It is cleared on every start, advance, ⏮ and run end. A
  second ⏭ inside a skip handover is the same skip.

**Surfaces:**
- `fast=true` (the 5 s sweep) comes from remote controllers (`SequencerForwardingPlayer.seekToNext` when not called
  internally), the widget NEXT, Android Auto and headset ⏭.
- The in-app ⏭ on Now Playing and the mini bar acts at once with the Skip fade. A second tap during the mix upgrades
  it to fast. This is needs_levi item M2; the reason is that a `combinedClickable` double-tap detector would delay
  every tap.
- Never put a `pointerInput` press detector over the ⏭ clickable. It swallowed taps on iOS (release blocker
  0c696c9a).

### 6.5 The PocketDJ selector (P2-DJ-4, P2-DJ-10)
**`DjSetPlanner`** is pure and bit-identical to iOS `DJSetPlanner.swift`. Its rules:
- tempo bands of 10 BPM, at least 3 songs per band;
- seeded wave length 2–3 and pocket length 3–4 via `hash`;
- weights .35/.2/.2/.25, order bonus .02, aging bonus .03, neutral .5;
- near-adjacent Camelot .3–.8;
- **artist spacing 4, with the scarcity rule** (cdbf9e87, the pocket-collapse fix).

It reuses `foldBpm`, `camelotRelatedness`, `Genre.category` and `creditArtistKeys`.

`State` JSON matches iOS:
- `seed` is a UInt64, encoded and decoded as unsigned, because values of 2^63 or more occur;
- `lastAccountedUid`;
- `pocketAnchor`;
- `direction`.

**`DjPlannerDriver`** keeps the **next-up pick sacred**:
- `onRowLandedNext` sets `djUserNext`.
- The pick is never moved, nothing is placed ahead of it, there is one pick at a time, it is spent when it plays, and
  it re-anchors the wave.
- A stall-hop deferred row becomes the pick.
- Random jukebox inserts are drawn from after a held pick.

**Fixed rows** (never re-ordered):
- the pick;
- album-run blocks;
- rows with a playback rip, lane fetch or buffer stream in flight;
- rows deferred 12 or more times;
- the next row when it is local, buffering, mid-transition, under 30 s of runway, or of unknown length.

**Re-plan:**
- It is debounced 1 s and triggered by DJ on, each advance, a membership landing, and edits.
- It writes ONE uid-verified re-order of the next 40 rows. Duplicate uids make it bail.
- Our own re-order never re-triggers it.
- There is no re-plan while a Remote session is attached.
- Shuffle is superseded while DJ is on.
- Membership is loaded off-main from `ListeningPocketsCollections`, once per DJ-on.
- Rows appended by a pocket run are planner material.

### 6.6 Loudness leveling (P2-DJ-2, P2-DJ-11)
**`Loudness.kt`** is a BS.1770 meter:
- K-weighting pre-filter plus RLB biquads;
- 400 ms blocks with 75 % overlap;
- gates at −70 LUFS absolute and −10 LU relative;
- a mono sum.

It decodes through `audio/core` `AudioDecoder`/`Mp3Decoder`.

**`LoudnessCache`** is `filesDir/loudness.json`, keyed by songId + byte size + segment, so a shared album side is
measured per song slice. It is single-flight per key, remembers a failure for the launch, and is cancellable.
**`LoudnessLeveling`** targets −14 LUFS, clamped to −12…+6 dB.

**`DjLeveling` rules:**
- Only a STORED result re-applies gain.
- A result landing mid-play ramps over 2 s in 20 ms steps. The incoming gain lands over 150 ms at fade start.
- There is never a step change. Unknown loudness means 0 dB.
- The listener's volume sits on top, and the limiter catches positive-gain peaks.
- Leveling is active only while DJ is on AND the Volume toggle is on. DJ off or session end cancels running analyses
  and levels to 0 dB.

### 6.7 Progressive analysis (P2-DJ-3)
`AudioAnalysis` provides:
- a 20 s quick window from about 30 % into the song, or the 15–30 s head for growing files;
- then a full pass.

`BeatDetect` gains a confidence output, and `KeyDetector` gains strength and `maxSeconds`. Studio callers are
unchanged.

**Precedence:** server grid/catalog > full on-device result > a confident quick hint (BPM confidence at least 0.3, key
strength at least 0.7) > nothing. A hint never replaces a final. Hint leveling is clamped to ±4 dB and labelled
"estimated".

**`AudioAnalysisCache`** is `analysis.json`:
- LRU of 5,000 finals;
- hints kept for the launch only;
- saves debounced 1 s and done off-main;
- tolerant decode.

**`AudioAnalysisScheduler`:**
- runs one pass at a time on `Dispatchers.Default`;
- priority order: current → next-up pick → planned next → the 40-row window;
- pauses under `PowerManager.isPowerSaveMode` or thermal status SEVERE or above (the Android mapping of iOS Low Power
  / serious thermal);
- re-checks a growing head every 5 s, at most 24 times;
- drops its queue when DJ is turned off.

A result re-plans only when a row's usable BPM or Camelot changed.

### 6.8 Automation display (P2-DJ-12)
`StateFlow<DjDisplay>` is sampled at about 16 Hz, only while automation runs. The panel binds the sliders and FX to
the *display* values. The display is read-only: listener values, FX Lock capture, the snapshot and settings never
see automated values. A touch acts on what is shown: a slider drag sets the listener value from the shown value and
ends the glide without a jump.

The leveling readout shows:
- "Leveling +3.2 dB" with a −12…+6 meter;
- "measuring…", "off" or "unavailable";
- "−4.5 dB → +3.2 dB" during a crossfade.

### 7.1 Crate stall (P2-MIX-1; iOS 1bad0e9d + dd1f190c)

## 8. Vinyl album sides and the album page

### 8.1 Layout model and side-file playback (P2-ALB-1, P2-ALB-3)
**`AlbumFileTimeline`** (pure, port of the iOS file):
- `Segment(songId, startMs)`, sorted by `(startMs, songId)`. A duplicate start keeps the first.
- `FADE_GRACE_MS = 15000`.
- `forKey` skips non-members, because a stale re-split id would end a real song early.
- `endMs(of)` = `min(exactEnd ?: detectedEnd + 15 s, nextStart)`. If the result is at or before the song's own start,
  it uses `nextStart` instead. The last song gets `null`, meaning the end of the file.

**`SegmentOverrides`** is derived on every catalog publish and `reapplyEdits`, owned by `CatalogRepository` as a
`StateFlow` so the playback layer reads it without UI:
- It covers only albums with `audioTracks.size == trackList.size`.
- Deltas are matched to the RAW album's segments by `trackNumber`. They are matched by position only when a delta
  has no `trackNumber`.
- On a count mismatch it skips the album; it never guesses.

**Invariant: every reader of a shared-file start goes through the override.** That covers:
- `RipsRepository.effectiveStartMs`;
- `BurnStore.startMs`;
- `PlayResolver`;
- `MixStreamLoader`;
- `MixGraph`;
- `MixWaveform`;
- `StudioGraph`;
- `CuesScreen` and `CueSeek`.

**Bug fixed in wave 1 (P2-ALB-1).** The set and Now Playing played a burned analog song from its per-song **cut**.
iOS never does that: cuts are burn-export sidecars, and the server still cuts them at catalog length. The sequencer
and `resolveBurnedFirst` now use `localUrlForPlayback`, which is the side file plus a window. `localUrlPreferringCut`
stays for Mix and Studio only.

**`AnalogWindow.endMs`** (P2-ALB-3) is used everywhere an analog window ends. A lone song ends:
- at its edited end, exactly;
- otherwise at the detected end + 15 s, capped at the next start;
- with no timeline, at the old `startMs + length`.

### 8.2 Edits document (P2-ALB-2)
- The file is migrated once from `backup-edits.json` to `pocketdj-edits.json`, with the iOS shape
  `{schemaVersion, albums, songs, meta?}`.
- It is registered as `SyncEntry("edits")`. A pull invalidates, re-applies and re-derives the overrides. A pull never
  pushes back; the doc is whole-document last-writer-wins.
- `EditsStore` is the write API. It stores deltas only, and an empty edit removes the entry.

### 8.3 Album runs (P2-ALB-4, P2-ALB-5)
**Mechanism (D6).** iOS plays a side with one `AVPlayerItem` and moves its boundaries. Android does the equivalent:
- **One ExoPlayer item per run**, clipped to `[leadIn ? 0 : songStart, END_OF_SOURCE)`.
- Per-song boundaries are armed by the sequencer through `PlayerPort.armBoundary(fileMs)` and
  `seekInFile(fileMs)`. The service implements them with `ExoPlayer.createMessage(...).setPosition(...)`, which is
  exact and survives Doze, with a 250 ms poll as the fallback. They are not done with `ClippingConfiguration`,
  because a clip change forces a re-prepare.
- **Seek BEFORE re-arming.** Otherwise a tick that still carries the old position fires the new song's end.
- The song is retitled with `replaceMediaItem` (same URI and clip, new metadata and mediaId). Media3 1.6.1 updates
  that in place. The emulator check is that no `STATE_BUFFERING` and no discontinuity appear.

**`albumRun`** is ported verbatim. The next row continues the run only when:
- it is the timeline's next segment;
- it is also `queue[pos+1]`, compared by `baseId`;
- the row won't replay (repeat-one and a repeat count greater than 1 break the run).

**Glide** happens only on a NATURAL boundary (an AdvanceInterceptor):
- Within `[curStart, next.start + 3000]`, the song is retargeted in place.
- A gap larger than 3 s means `seekInFile(next.start)`, then retarget.
- Glide declines when the DSP is engaged, Stem Lock is on, a deck is held, Apple Music or live audio is playing, or
  the DJ tail deck owns audio.

**Retarget in place** runs the normal start bookkeeping without the load:
- generation bump, `playTask` cancel and supersede;
- skip-tracker re-arm and repeat count;
- history, stats and the PlayEvent;
- dead-air first audio;
- rip window and prefetch;
- persist with `positionMs 0`.

The title comes from the CURRENT catalog, so a rename shows at once.

**Other run rules:**
- ⏭/⏮ inside a loaded side seek in place. A skip while paused starts playback.
- Lead-in plays from file 0:00 only for a fresh first song that starts a run. It is a one-shot, never a negative cue
  and never on resume.
- The last song, when reached through the album, plays to the end of the file.
- `NextRowPreloader` never preloads a run continuation.

**Song-relative clocks (P2-ALB-5).** `SequencerForwardingPlayer` reports position and duration relative to the song
(clamped to at least 0, so a lead-in shows 0:00). It maps a remote `seekTo` back to file milliseconds. The skip
tracker, snapshot and widget use song-relative values.

The waveform uses two APIs: `seekAlbumFile(fileMs)` and `cueNextStart(songId, atMs)` (a one-shot that expires after
30 s).

Album ▶ now goes through `collections.playNow(SOURCE_ALBUM)`, the same path as Shuffle. The `playAlbumQueue`
truncation hack is deleted.

### 8.4 Waveform editor (P2-ALB-6)
This is a port of `AlbumWaveformEditor.swift`, built from a Compose `Canvas` and `pointerInput`.
- **Image and regions.** The image is `rips/waveforms/<albumId>.png`, loaded with Coil. Regions are tinted by
  Camelot key at 0.26 alpha with a 3 dp top edge and end at the PLAYBACK end, so gaps stay untinted.
- **Gestures.** Tap or horizontal drag plays from that point. A **vertical pan scrolls the list instead**: the
  direction is decided before the gesture is consumed. Double-tap renames.
- **Handles.** The handle band is 22 dp tall above a 96 dp waveform. Handles clamp with `minGapMs = 1000`. A nudge
  bar offers −1 s, −0.1 s, +0.1 s, +1 s, Set to playhead and ✕.
- **Save.** Saving rebuilds one `AudioTrackEdit` per RAW segment. `deltas[i].startMs` and `deltas[i-1].endMs` are
  null when equal to raw. The pure save math lives in `AlbumBoundaryEdits.kt` and is tested.

### 8.5 Album page (P2-ALB-7, P2-LIB-5)
- On phones (`WindowWidthSizeClass.Compact`), rows have two lines:
  - line 1: the title (up to 2 lines) and the E badge;
  - line 2: "BPM · key chip · time · up to 2 keywords". Keywords give way first.
- The artist name is a hotlink.
- An album queue menu and a long-press menu on each track.
- Stemify album.
- "Add to Apple Music again" for provisional `amrec_album_` albums.
- Optional inline slide-out player (G14).

### 8.6 Edit sheets (P2-ALB-8)
There are sheets to edit an album, a song and the audio-analysis segments. They store only the fields that differ
from the RAW row; `CatalogRepository` exposes the pre-overlay rows for this. Settings ▸ Edits offers export, import
(imported wins per id) and clear.

## 9. Library and Apple Music

### 9.1 Credentials guard and auth hold (P2-LIB-1)
**`sameServerHost`** (iOS 1bad0e9d + dd1f190c). A pulled EMPTY secret is ignored when the pulled URL points at the
same host as the local one. The comparison:
- trims whitespace, including newlines;
- accepts an exact string match;
- parses a scheme-less `host:port`;
- compares hosts case-insensitively;
- strips a trailing dot.

The guard Android has today compares exact URLs. That guard is what let one device re-point the rip URL to `:10000`
and wipe the rip token on every device in the fleet.

**The rip-server auth hold:**
- `RipError.unauthorized` records a token-scoped `rejectedToken` and `rejectedAt`. These are kept in memory only;
  never logged, never persisted.
- `authHoldoff` re-probes after 120 s.
- The hold clears when the token changes or when any authed call returns 2xx.
- Automatic callers hold off. User actions still try.
- The copy says the server rejected the token; it never says "server down".

### 9.2 Apple Music library source (P2-LIB-2, P2-LIB-3)
The Android MusicKit SDK has no library reads. The **Apple Music Web API** with the Music-User-Token does, which
makes this mapping an equivalent: `GET /v1/me/library/{songs,albums,playlists}`.
- **Store.** The doc shape matches iOS (`amlib_`/`amlibpl_` ids). The `albums` and `playlists` keys are optional, so a
  missing key never wipes the doc. A full run replaces the doc; an incremental run appends idempotently and advances
  `lastAddedMs`.
- **Indexer.** A WorkManager job runs after sign-in and daily.
- **Fold.** The library is folded into the merged catalog through the DiscoverAdds/ImportedSongs injection path, as
  source "Apple Music", distinct from the private "Apple Music (Local)". A song is superseded onto an indexed twin by
  `appleMusicId`, carrying `supersededAddedAt`.
- **Sync.** `SyncEntry("apple-music-library")`, whole-document last-writer-wins.

### 9.3 Store album page, edition swap, MUT reconnect (P2-LIB-4)
**`AlbumPreviewScreen`** replaces the recognizer's "open the Apple Music app" fallback. It is also where For You
release rows and Discover album taps go. Ownership comes only from the already-ported `AlbumOwnership`. Download uses
ONE shared poll loop against the concurrency-1 ripper, in a store-owned task that survives the screen closing.

**Edition swap.** The recognizer resolves the preferred edition before it adds anything (`EditionPolicy`). The order
is: add to the AM library, THEN rip+burn.

**MUT reconnect.** iOS re-mints a rejected Music-User-Token silently with `.ignoreCache`. Android cannot. When a sync
job fails with `AM <METHOD> <path> -> 401|403`, Android clears the MUT once and shows "Reconnect Apple Music" in
Settings ▸ Apple Music. A 401 from our own gateway never triggers this.

## 10. Pocket wheel and pocket runs

The audits' item-by-item constants are in `audits/pockets.md`; the iOS design doc is `docs/design/pocket-wheel.md`

### 10.1 Data plumbing first (P2-POC-1, P2-POC-2)

- **No new PlaySource.** No PlaySource case is added for runs, because older builds drop unknown sources.
- **Attribution: origin.** Every play records its origin:
  - `ShellActions.playSongIds(originId)`;
  - Android Auto source playlists pass their id;

### 10.2 Engine, palette, cache (P2-POC-3/4/5)
- **Engine.** Pure Kotlin ports of `PocketWheelModels`, `PocketMomentEngine` and `PocketProfile`. The mode tokens are
  persisted and never renamed. The engine computes 168 cells × modes, decayed and smoothed, rounded with `round6` for
  goldens. Tests read `apple/Tests/Fixtures/pocket-wheel-history.json`.
- **Palette.** `pocketdj-pocket-palette.json` is byte-compatible with iOS. Merge rule: the earliest
  `(assignedAtMs, slot)` wins. The 12 sRGB triples are copied exactly. Overflow colours use `oklchToSRGB` with a

- **Cache.** `PocketMomentCache` rebuilds off-main with a 5 s debounce and keeps a disk cache for an instant paint.

### 10.3 Best match (P2-POC-6)
`PocketBestMatch` has the tiers rich, neighbourhood, cloud, cold and empty. Each tier yields the same `PocketProfile`,
so the planner has no special cases. Continuity is negated when the recent skip rate is above 0.5. It returns 3
alternatives with distinct dominant collections, and the caption is honest about the tier.

The `InThePocketScorer` profile builders are refactored into internal helpers. They are not copied, and the golden
scorer tests stay green.

`modeNow` is decided in this order:
1. Android Auto connected → carPlay.
2. Otherwise, the motion timeline's last 5 min.
3. Otherwise, the place engine's trip guess.

### 10.4 Runs (P2-POC-7, P2-POC-8, P2-POC-15)
**Planner** (pure, seeded `SplitMix64` + `weightedDraw`, identical to iOS):
- The run is **derived**, never a replay.
- The ≥60 % fresh floor is **paced over every prefix**.
- Familiarity counts only when negative.
- No artist appears twice within 4 slots, and at most 6 per 100.
- At least 20 % of the run is newcomers.
- The first 3 rows are biased toward songs that start instantly.

**`PocketRunStore`** is app-scoped and persisted to `pocketdj-pocket-run.json`:
```
start(profile) ─▶ RUNNING(owns sequencer: isRunning && source == "pwr_<id>")
RUNNING ─1 Hz evaluate (bounded tail walk; SkipTracker→history verdicts only)─▶ bans/tuning → debounced replan (1.5 s) → replaceUpcoming
RUNNING ─queue taken by something else─▶ GRACE(10 s, learn-only) ─▶ DETACHED
RUNNING ─100th play-through─▶ FINISHED (never start a 101st) ─▶ past[]
any ─Clear this pocket─▶ stop() → past[], queue stopped
restored & not playing ─▶ HELD (no per-tick work)
```
- **Verdicts.** There is never a second skip pipeline. Bans come from THIS run only (W5).
- **Replacements.** A replacement clears the artist-spacing window (cdbf9e87). Top-up runs off-main with a 30 s
  backoff. Rows are edition-stamped.
- **W2 accounting.** `rowsNeeded` counts the sounding row as done once it is 90 % played, and keeps one spare row.
- **Repeat.** It is forced off through the PB-3 provider.
- **Re-tuned badge.** "Re-tuned ✦" lights only rows that actually landed, and clears 4 s after the latest swap.
- **W7 Mix path.** If at least 10 songs are deck-loadable, the run goes to `MixFacade.startAutoMixSongs`. The Mix path
  has no live re-plan (accepted on iOS).

### 10.5 Wheel UI (P2-POC-9, P2-POC-10)
**The wheel:**
- A pure port of `WheelLayout`; the Canvas draws only from the precomputed layout.
- Midnight sits at 12 o'clock, going clockwise, and Monday is the innermost ring.
- Polar hit-testing; scrub shows a Popup callout.
- Mode chips, a fisheye day picker and a now needle.
- The centre ▶ shows progress. Long-press, or a secondary click on mouse or ChromeOS, opens a menu: Clear this pocket
  / Start a new pocket for now / Not this?.
- TalkBack gets a node per ring with custom ±hour actions.

**The moment card** is a ModalBottomSheet on phones and a side pane at 600 dp or wider.

**History ▸ Pockets** has a Wheel | List segment, with Wheel as the default. The List segment is hidden if the user
declined cloud pockets. In List, Play starts a derived run, and "Play the original songs" is the secondary action.

### 10.6 Motion (P2-POC-11, P2-POC-12)
**Mapping (D5).** iOS runs a retroactive `CMMotionActivityManager` query. Android has no retroactive history, so it
uses the **Activity Recognition Transition API** (play-services-location, already a dependency):
- It registers ENTER/EXIT transitions for RUNNING, WALKING, ON_BICYCLE, IN_VEHICLE and STILL, delivered to a manifest
  receiver through a mutable PendingIntent.
- It re-registers on app start, on `BOOT_COMPLETED` and on `MY_PACKAGE_REPLACED`.
- Transitions build a device-local 7-day timeline, `pocketdj-motion-timeline.json`.

The pure `MotionSettle` then runs over the timeline exactly as on iOS. Settled motion is stamped write-once on this
install's plays.

**Permissions and the opt-in:**
- `ACTIVITY_RECOGNITION` with a **prominent-disclosure dialog before the runtime request**.
- `RECEIVE_BOOT_COMPLETED`.
- The opt-in defaults to off. Raw motion never leaves the device; only the derived sensor mode is uploaded, and only
  while the toggle is on.

**Adapt to activity.** A run re-targets once per mode per run, after a 180 s sustained change.

### 10.7 Upload Phase 6 (P2-POC-13)
**Never send `mode` or `run` before the server has echoed `caps:["wheel"]`.** An old Lambda returns 2xx but drops
them, and because of fingerprinting they would never be re-sent. The rules:
- Fingerprint suffixes are added only when present, so existing fingerprints stay byte-identical.
- When not sent, `mode` and `run` are absent, never null.

### 10.8 Goldens (P2-POC-14)
A Swift test, run only when `PDJ_DUMP_PARITY=1`, dumps `apple/Tests/Fixtures/pocket-wheel-parity.json`:
- moments;
- the best match at a fixed Now;
- the first 100 rows for a seed;
- the post-Drake replan.

Android then asserts against it to 1e-9. This package is the one explicit exception to "don't touch `apple/`". The
Swift run goes through `one-at-a-time.sh`.

### 10.9 Surfaces (P2-POC-16)
- **Android Auto.** A "▶ Pocket for now" row and a "Pockets right now" list (the top 5 moments within ±1 h). With the
  car connected, the mode is carPlay. A failed play shows an error and never opens an empty player.
- **Voice.** `ShellActions.playPocketForNow()` is reached from a static shortcut, `pocketdj://pocket/now`, and the
  Assistant phrases "my pocket" and "pocket for now".

## 11. Remote (Listen Together, Backseat, Mix Together)

### 11.1 Transport mapping (D3)
iOS has exactly two `RemoteTransport` implementations: SharePlay (`GroupSessionTransport`) and loopback. **Joining an
iOS SharePlay session from Android is platform-impossible** (see §16).

Android gets the same capability by porting every transport-agnostic layer verbatim and running it over:
1. **Google Nearby Connections**, the primary transport (P2-REM-9):
   - `P2P_STAR`. The host advertises and relays participant→participant traffic. Nothing is ever echoed to the
     sender.
   - No server, and it works offline. This covers Backseat in a car, and the default jukebox URL is blank.
   - Its latency suits Mix Together's 40 ms drift floor.
   - Participant ids are per-session UUIDs sent in the first frame. They are never Nearby endpoint ids, because the
     election compares ids across devices.
   - The token is checked in the connection request.
   - `maxStateBytes` is about 30 KB; window halving handles the smaller cap.
   - Permissions: `BLUETOOTH_SCAN` (neverForLocation), `BLUETOOTH_ADVERTISE`, `BLUETOOTH_CONNECT` and
     `NEARBY_WIFI_DEVICES` (neverForLocation). They are requested at start or join, with a rationale sheet.
   - A controller with no playback stays alive with a `connectedDevice` foreground service, or the media service
     keep-alive. This must be verified on a device.
2. **The broker**, optional (P2-REM-10). Long-poll `/remote` routes on `scripts/jukebox-server.mjs`. Plain HTTP was
   chosen because Funnel, Lambda and URLSession all handle it, and URLSession can't talk to API Gateway WebSockets.
   The wire is byte-identical, so a future iOS `BrokerTransport` could join Android sessions with no Android change.
   It is not deployed without Levi's word.

### 11.2 Wire, queue model, clock, send queue (P2-REM-1, P2-REM-2)
**Envelope:** `{"v":1,"kind":…,"payload":<standard base64 of body JSON>}`.
- An unknown kind or `v > 1` is ignored.
- An undecodable body is dropped.
- Times are epoch-ms Doubles.

**`RemoteCommand`** needs a hand-written serializer for Swift's synthesized enum Codable. Every case is a single-key
object, and an unlabeled associated value is `_0`. For example:
- `{"setPlaying":{"_0":true}}`
- `{"playPause":{}}`
- `{"move":{"rid":…,"toUpcomingOffset":2}}`

**`RemoteQueueModel`:**
- Host-authoritative.
- Rows are addressed by rid.
- The revision bumps only on a real change.
- `advanced(fromRid)` applies only while that row is current, so N speakers advance once.
- `play` resets shuffle, and `canonicalUpcoming` supports unshuffle.
- The window is 20 behind and 200 ahead.

**`SharedClock`:** best of 8 samples by lowest RTT (not the average). It resets on a host change.

**`RemoteSendQueue`:**
- Two lanes with ONE worker coroutine each, never a coroutine per message. That once let a later state overtake an
  earlier one on iOS.
- Reliable sends retry at 0.25 s and 1.0 s.
- State and heartbeats are coalesced per recipient.
- Caps are 256 reliable and 32 unreliable.
- A peer that isn't resolvable yet gets a buffer of 32, for up to 16 peers.

### 11.3 Player seams and the gate (P2-PB-3, P2-REM-3, P2-REM-4)
`PlaybackController` is the funnel: every Android transport surface goes through the sequencer's `transportGate`.
That covers:
- MediaSession callbacks, including Bluetooth/headset and the Android Auto session;
- `WidgetBridge`;
- `ShellActions` quick play;
- Assistant.

**A controller plays nothing.**
- `localStart` (a cascade retry or a stray reclaim) is refused and NOT forwarded.
- `silenceForController` also holds the NP DSP host and the Mix decks, through registered silencers. It is re-asserted
  every tick, because a pause racing a pending start would otherwise be overridden.
- `isSystemPaused` comes from `PlaybackService`'s pause classification: noisy, permanent loss, or a transient loss
  that never resumed.

**`RemoteSongResolver`** is the rights boundary. Its ladder:
1. own songId;
2. the catalog song with that `appleMusicId`;
3. `am:<id>`, if the user's AM is usable;
4. an exact normalized title|artist key;
5. fuzzy match, for the current row and the next 3 only;
6. otherwise, unavailable.

A rip URL, presigned link or token never goes on the wire. A cached resolution always gets a fresh uid.

### 11.4 Session controller (P2-REM-5, P2-REM-6)
`RemoteSessionController` is app-scoped in `RemoteGraph` and ticks every 0.5 s on Main.

**Election and host:**
- `shouldYield` is symmetric: an active session beats an empty one, then the newer revision wins, then the lower id.
  **An empty host never wipes a real session.**
- A joiner re-hellos after 8 s and self-hosts only when alone.
- When the host leaves, the lowest remaining id takes over.

**State flow:**
- State goes out on a revision change, to a joiner, and on request.
- A heartbeat goes out every 2 s.
- A receiver applies structure only from a newer revision.
- A missed revision triggers a `stateRequest`, retried from 2 s doubling to 16 s.
- The size cap is `min(60 KB, transport cap)`; the window halves until the state fits.
- When the tail drops below 100 rows, the host refills 200 from its local set.

**Reconcile** (on each speaker) picks the cheapest move:
- a tail edit;
- `jumpToUpcoming(uid, atMs)`;
- a fresh `play(startIndex, atMs, startPaused)`.

**Drift:**
- The threshold is 750 ms, or 2,000 ms when the AM clock is coarse.
- Act only after 2 strikes, then a 5 s cooldown. Never correct while buffering.
- A position change with a new revision is a session seek, applied at once.
- A jump of more than 3 s between ticks is a scrub. The landing of our own seek is not.
- A ▶/⏸ that didn't take is re-issued after 2 s.
- A local edit holds reconcile for 3 s (`pendingHold`).

**Local changes** map from `TransitionCause` (§2.1):

| Cause | Result |
|---|---|
| USER | Send a command |
| NATURAL_END | `advanced(fromRid)`, only within 10 s of the row's end |
| AUTO_SKIP / STALL_HOP / UNPLAYABLE | Mark the row unplayable here |
| REMOTE | Never echo |

A local stop never pauses everyone.

**pausedHere.** A system pause sets `pausedHere`. The app **never resumes out of the phone speaker on its own**: only
▶ or Rejoin resumes, at the session position.

**Suspensions while a session is live:**
- DJ Mode is suspended.
- Auto-DJ is refused while mixing together: "Auto DJ is off while you mix together." The Assistant and the Auto Mix
  tab say the same.

### 11.5 UI (P2-REM-7, P2-REM-8)
**`RemoteScreen`** has the start cards (Listen Together / Backseat), invite and join (QR, code, nearby hosts), and the
role picker. The rest of the screen:
- participants with Host and role badges, plus an "N songs can't play here" note;
- the transport, which sends commands only, never to the local player;
- Up Next edits;
- search-to-add;
- the "Paused on this device" card with Rejoin.

**`JukeboxHubScreen`:**
- A Hero | Remote switch pinned in the top bar.
- The `jukeboxPanelMode` raw values `"Jukebox Hero"`/`"Remote"` are kept.
- The panel flips to Remote when a session goes active.
- `pocketdj://remote` and `pocketdj://remote/join/<code>` route here.
- The retired `Remote` tab token maps to the Jukebox panel.

A DEBUG-only showcase seed, `pdj.seedRemote=showcase`, supports store screenshots. The UI stays hidden until
`ParityFlags.REMOTE`.

### 11.6 Mix Together (P2-REM-11, P2-REM-12, P2-REM-13)
**Ordering and echo:**
- A participant's gesture is a proposal; the host sequences it; every device applies events in host order.
- No echo. A sender's own pending value shadows older ones, and pending values expire after 2 s.
- Continuous controls coalesce at 50 ms and seeks at 250 ms, each with a trailing final send.
- A sequence gap older than 1.5 s triggers a snapshot request, retried at 3/6/12/24/48 s.

**Ownership:** the host owns deck A, and the first `caps:["mix"]` joiner owns deck B.

**MixEngine seams:**
- `gestureTap(cause)`, emitted beside `MixRecordingHooks.emit`;
- `applyingRemote` (no tap, no session-log record);
- `syncPlay(atLocalMs)` on the render clock, fired early by the AudioTrack latency;
- a rate nudge of at most 1 %;
- an exact-window loop set;
- a whole-board diff;
- an Auto-DJ block with a reason;
- persistence suspended while live, so the saved mix survives;
- silence for a controller.

**Drift:**
- Starts are anchored `startLead` 300 ms ahead (min 60, max 2,000).
- The threshold is 40 ms + both clocks' uncertainty + 20 ms.
- Act after 2 strikes. Under 250 ms, nudge; otherwise re-seek. Cooldown 4 s.
- Beats staler than 1.5 s are ignored. **Looping decks compare PHASE inside the loop.**

**Local rules:**
- System causes stay local: a held deck rejoins.
- Cue/PFL, the meter, recording and the session log stay local.

Android Mix decks are mp3-only (L6). A row that can't load is "isn't available on this device — this deck stays
silent here".

## 13. System surfaces

### 13.1 Recommendation thumbs (P2-SURF-1)
`NowPlayingFeedback` is the one shared rec target. It is a port of `currentRecTarget`, `currentRecVerdict` and
`recordNowPlayingFeedback`:
- **Target.** The target is the sequencer row plus `scopeForPlaying`. It is null unless the standalone player owns
  audio.
- **Toggle.** A second tap on the lit thumb clears it.
- **👍.** An accepted 👍 also adds the song to the scoped collection. Reserved scopes (zone, new) record feedback only,
  and an undo never un-adds.
- **👎.** A 👎 never skips or pauses.

NP, the notification, the widget and Auto all consume this same object. Its seam is installed from `BrowseGraph`.

For You scope: every `publishNowPlaying` fires `onPlaybackReplaced`, which calls `endPlaybackScope`. Tile play calls
`beginPlayback` AFTER `playNow` returns, which is the iOS order.

### 13.2 Media buttons (P2-SURF-2)
`setMediaButtonPreferences` (Media3 1.6.1) replaces `setCustomLayout`:
- ♥ shows only when ExoPlayer is the owner, never on a Mix-owned card.
- Shuffle and repeat show only while a set runs. Repeat shows the EFFECTIVE mode and is inert during a run.
- The 👍/👎 pair shows only for a rec target, all-or-nothing.

These use trusted `SessionCommand`s and are rebuilt on `RunTransportBus.stateChanged`. Android Auto renders the same
preferences.

### 13.3 Widget (P2-SURF-3)
- The snapshot carries `recVerdict` and `recScope`.
- `WidgetCommand` gains an additive `scope`.
- A verdict applies to the **snapshot's** song and scope, never to whatever is current when the command drains.
- Verdicts never expire in the queue.
- The repeat glyph shows the effective mode.

### 13.4 Voice and actions (P2-SURF-4, -5, -6, -10, -11, -12)
**Mapping (D4).** Every iOS `IntentServices` door becomes a `ShellActions` method. Each method runs the onboarding
veto and `ensureReady` (the seed-then-return budget). The doors to those methods are:
- deep links, which always work;
- launcher shortcuts;
- Assistant `MEDIA_PLAY_FROM_SEARCH` and `SEARCH_ACTION`;
- App Actions capabilities, declared but best-effort, since Google is winding App Actions down;
- AppFunctions on API 36 and up, runtime-gated, with exact pinned versions.

**Matching rules:**
- **Song matching** (`IntentSongMatcher`): match the whole phrase, and also split at the LAST " by ". Tiers run exact
  > base > prefix > whole word > typo, where typo runs only when nothing literal matched. Results are deduped by
  recording.
- **Collection matching** is strict. Strip "my" and "the", and a trailing "playlist", "pocket" or "collection". Then
  equals > prefix > contains. **Never initials or subsequence** (922ea73c).

**Behaviour rules:**
- **Add to collection.** A pocket gets membership. A playlist gets its FIRST chapter. An existing member is never
  toggled off, and the reserved Now Playing set is never a target.
- **"This song".** It means the audible owner.
- **Stems by voice.** They follow the panel order exactly: Mix Mode on → explain via the chip if mix isn't available
  yet → engage → stem mode → mute only if unmuted. Voice is refused while the Mix tab is live.
- **Create pocket.** A deterministic brief parser and a fitter. Gemini Nano (ML Kit Prompt API) is used only when it
  is available at runtime.

### 13.5 Android Auto (P2-SURF-7, -8, -9)
- **For You tab.** It is frozen: built from the cached feed with the phone's `ForYouTiles.build`, and **never
  refreshed or ranked on connect**. Release rows are `rel:`. On a cold cache it shows a note instead. It respects
  `ROOT_CHILDREN_LIMIT`.
- **Up Next.** A browsable node keyed by uid, with per-row command buttons. There is no fake Timeline (D11).
- **Mix tab live controls.** All scoped to the LEAD deck. Tempo and pitch rows are disabled mid-transition. A stem
  mute with stems off turns stems on first.
- **Jukebox QR.** It is always present, as `content://` artwork.

## 15. Release, verification, Play declarations (P2-REL-1)

**Per wave.** `android/specs/parity2/wave-workflow.js` runs every wave in four stages:
1. Sonnet implements each package in its own worktree.
2. Sonnet reviews each package adversarially.
3. Sonnet fixes the findings.
4. One integrator merges the wave and runs the full JVM suite plus the emulator steps.

Each package has these inputs:
- `emulator_steps`: steps that adb can drive. Seed data comes from Settings ▸ Debug (Seed rip playlist / Seed setlist /
  Burn first 3 / Seed 60 AM batch / AutoDJ / Auto browse smoke) and DEBUG launch extras (`pdj.*`).
- `device_only`: real-device checks, collected into `DEVICE-CHECKLIST.md`.

**Release cuts.** RC-1 after wave 5, RC-2 after wave 9, full after wave 11. `P2-REL-1` can run at any cut with its
dependencies relaxed to whatever has merged.

**Play declarations:**
- **Data safety:** Fitness info (physical activity) is collected, linked, and used for app functionality and
  personalization; it is not shared and not used for ads. The privacy policy needs a motion line.
- **Permissions:** Nearby and Bluetooth are used for app functionality only. `neverForLocation` is set where it
  applies.
- **App Actions:** shortcuts.xml capabilities need a Play Console upload.

**Release build.** `android/scripts/release-aab.sh` builds from main, with `versionCode` set to the unix timestamp.
The rollout runs in this order:
1. Upload to Internal testing.
2. Run the device checklist.
3. Roll out to production in stages, starting at 20 % (needs_levi default).
