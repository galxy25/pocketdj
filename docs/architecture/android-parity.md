# PocketDJ — Android parity architecture

> **Program design document** for bringing the Android client to feature parity with the
> iOS app (`apple/PocketDJ`). It is the cross-cutting half of the implementer's spec; the
> other half is the per-package roadmap entry plus the per-area audit. Status and progress
> live in [`ARCHITECTURE-ANDROID.md`](../ARCHITECTURE-ANDROID.md) (the living doc) and in
> `android/specs/parity/PROGRESS.md`; this file records **decisions and the plan**, and
> changes only when a decision changes.
>
> Sources of truth, in precedence order:
> 1. `android/specs/parity/roadmap.json` — 15 decisions, 22 N/A entries, **116 packages in 22 waves** (generated by `android/specs/parity/tools/build_roadmap.py`; edit `spec_*.py`, never the JSON).
> 2. `android/specs/parity/audits/{playback,mix,studio,games,collections,browse,services,surfaces}.json` — eight per-area audits: feature inventory (DONE/PARTIAL/MISSING/NA with iOS and Android file pointers), area architecture, area decisions, original package specs.
> 3. This document — the audits' architectures condensed and **reconciled** with the roadmap decisions. Where an audit and this doc disagree (e.g. the Mix audit's `MixService`, the Services audit's `SecretBox`), this doc wins because the roadmap decision superseded the audit.

Baseline at the time of writing (branch `feat/android-parity`, 2026-10-27): 79 Kotlin
source files, **275 JVM `@Test`s**, six bottom-bar destinations, Phase-1 features built
(Browser, History, Jukebox host, catalog, playback facade, collections document). Audit
totals across the eight areas: **267 features — 28 DONE · 39 PARTIAL · 168 MISSING ·
32 N/A.**

## 1. Locked platform decisions (inherited, not relitigated)

Kotlin 2 + Compose Material 3 · single `MainActivity` + Navigation Compose · minSdk 35 /
target 36 · Media3/ExoPlayer + MediaSession · OkHttp + kotlinx.serialization + Coil ·
CloudFront catalog, offline-first disk cache · **Apple Music via the vendored native
MusicKit AARs** (sign-in + DRM full-track playback, device-only) · **NO CloudKit** ·
rip-server and jukebox-broker HTTP APIs unchanged. Package root `com.levi.pocketdj`,
Gradle root `android/`.

## 2. Cross-cutting decisions (roadmap D1–D15) and why

Each decision names the package that lands it. Implementers follow these even when the
area audit they are reading says otherwise.

### D1 — One native audio layer: shared `audio/` core; Kotlin pull-graph on `AudioTrack` for the Mix; Oboe sink + small C++ core for the Studio
`com.levi.pocketdj.audio` (**MIX-2**) is the single platform audio substrate: an `AudioSink`
interface with `AudioTrackSink` (float PCM, `PERFORMANCE_MODE_LOW_LATENCY`, a dedicated
`THREAD_PRIORITY_URGENT_AUDIO` render thread) and, once the NDK module exists, `OboeSink`
(**STU-2**); both pull the same `RenderGraph`/`PcmSource` API. One MediaCodec decoder
(`Mp3Decoder` + generic `AudioDecoder`), one `OfflineRenderer` for JVM/instrumented tests,
one `RenderClock`/`FloatRing`/`Voice`/`VoiceGroup` (four stems start on ONE render frame),
one `AudioDiag`. The Mix DSP engine is a Kotlin in-process pull graph (**MIX-3** DSP nodes,
**MIX-4** graph) rendered by `AudioTrackSink`, with per-deck time/pitch via Media3's public
`SonicAudioProcessor` (media3-common 1.6.1) — **no NDK on the Mix path in v1**; moving the
Mix onto `OboeSink` later is a one-line sink swap. The Studio keeps a C++ core
(`cpp/pdjdsp`: TinySoundFont SF2 voices, Signalsmith Stretch for OFFLINE stretch, ported
TrackFX/MasterFX kernels, multitrack sum) behind a thin JNI surface because a playable
SoundFont/MIDI latency needs a native data callback; all scheduling, state and musical
math stay in Kotlin. Now Playing's F4 mini-panel and Stem Lock (**MIX-18**) reuse `Voice` +
`Handover` from the Mix graph rather than forking.

*Why:* the Mix audit proved stems/handover/cue/limiter force an in-process mixer and chose
Kotlin+AudioTrack; the Studio audit proved SF2 synthesis needs Oboe. Two platform layers
would have duplicated decode, render-thread discipline (never allocate or lock on the
callback), re-prime-after-route-change and the test renderer. This resolves the living
doc's open question #1 (see §3.2 for the accepted Sonic quality cost).

### D2 — One MediaSession, one audio owner: `SessionSwitchboard` in the playback core; Mix/Studio/games present `TransportOwner` facades
`PlaybackService` hosts the ONLY `MediaSession` (upgraded to `MediaLibrarySession` by
**SURF-8**). **PB-2** merges the audits' SessionSwitchboard, SessionPlayerArbiter,
TransportOwner, SetGatedPlayer and FavoriteSeam into `playback/session/`: the engine that
last STARTED audio owns the card; a restored-never-sounded engine is not a remote target;
starting one owner pauses the other. The Mix does **not** get its own MediaSessionService:
`MixSessionPlayer : SimpleBasePlayer` (**MIX-11**) implements `TransportOwner` and is handed
to the session via `SessionSwitchboard.setOwner`, which also keeps the foreground service
alive while the Mix renders. Apple Music rows use `AppleMusicPlayerAdapter` the same way
(**PB-8**). Game runs ride the sequencer under a run tag (**GM-3**), ExoPlayer-only rows.

*Why:* the Playback, Mix and Surfaces audits each described an arbiter; the iOS
"impersonate" rule is one card ever. A second session would break lock-screen, Auto and
widget parity and double the manifest/foreground surface.

### D3 — Shell + DI extension points: `FeatureModule` + one sidecar graph per area, settings section registry, per-package settings keys
**SURF-1** (wave 1) creates `shell/FeatureModule.kt` and eight sidecar graphs
`di/{Playback,Mix,Studio,Games,Collections,Browse,Services,Shell}Graph.kt`, each
implementing `FeatureModule { navEntries, settingsSections, deepLinkHandlers, flushables,
resetHooks, syncEntries, rowResolvers, playOutcomeListeners, periodicWork }`. `AppGraph`
lists the eight ONCE; `ShellNavigation`, `SettingsScreen`, `DeepLinkDispatcher`,
`FlushRegistry`, `AppResetService`, `SyncRegistry`, `PlaybackController` and
`WorkScheduler` consume the aggregated lists. `AppSettingsStore` becomes a generic typed
store over `PrefKey<T>`; every later package declares its keys in its OWN `*Settings.kt`
(e.g. `data/search/SearchSettings.kt`). **Result: after wave 1 no package edits
`MainActivity`, `AppGraph`, `AppSettingsStore`, `SettingsScreen` or `PocketDjDestination`**
— they add files and edit only their area's sidecar.

*Why:* 37 audit packages wanted `AppGraph`, 32 `AppSettingsStore`, 15 `MainActivity`,
15 the Manifest. With ≤6 packages per wave and one-editor-per-hot-file, that would have
serialized the whole program; registries make the hot files write-once.

### D4 — Hot-file budget: build files, Manifest and permissions swept once in wave 1
SURF-1 adds every planned dependency to the version catalog in one pass (work-runtime-ktx +
work-testing, lifecycle-process, security-crypto, glance-appwidget,
material3-adaptive-navigation-suite, media3-common, play-services-location, Compose
foundation DnD, mockwebserver) and declares in the Manifest: `RECORD_AUDIO`,
`POST_NOTIFICATIONS`, `FOREGROUND_SERVICE_DATA_SYNC`, `FOREGROUND_SERVICE_MEDIA_PLAYBACK`,
`BLUETOOTH_CONNECT/SCAN`, a `FileProvider` with a broad `res/xml/file_paths.xml`, an empty
`res/xml/shortcuts.xml` meta-data and `buildConfigField DIAG_CHANNEL`. Remaining Manifest
editors: SURF-2 (Application class), SURF-4 (deep-link/file-open filters incl. the parked
`pocketdj://mwf` route), SURF-7 (widget receiver), SURF-8 (Android Auto), COL-20 (location
permissions). Remaining Gradle editors: STU-2 (externalNativeBuild/Oboe/abiFilters), BRW-17
(ShazamKit AAR). Everything else adds files.

The ten hot files (`roadmap.json#hot_files`): `MainActivity.kt`, `shell/ShellNavigation.kt`,
`navigation/PocketDjDestination.kt`, `di/AppGraph.kt`, `data/settings/AppSettingsStore.kt`,
`screens/settings/SettingsScreen.kt`, `screens/settings/SettingsSections.kt`,
`AndroidManifest.xml`, `app/build.gradle.kts`, `gradle/libs.versions.toml`.

### D5 — ONE offline downloads/burn store (`data/burns` + `data/transfers`), WorkManager-backed
Mix DL-1 and Services BURN-1/XFER-1 merge into **SVC-2** (BurnStore core: iOS
`pocketdj-burns.json` v1 ledger, byte-identical descriptive file names, sidecar,
all-4-or-nothing stems `stem-<id>-<part>.mp3`, beat-grid sidecars `analysis-<id>.json`,
reconcile, eviction planner, in-process serial loop) and **SVC-3** (TransferCoordinator over
WorkManager: records persisted BEFORE enqueue, foreground progress notification, bearer
policy, `.part` + atomic rename, rip-reconcile periodic worker). Burns live app-private
under `filesDir/burns/` behind a single `BurnFolder` root resolver; the SAF user folder is
**SVC-14**. `MixStreamLoader` (**MIX-6**) adopts finished streams into the SAME store;
Studio's `LocalAudioCache` (**STU-3**) is a thin façade over BurnStore; `StorageService`
categories BURNS/STEMS/MIX_STREAM_CACHE/MIX_SESSIONS/STUDIO come from it.

*Why:* two ledgers for the same mp3s would double disk use and break the iOS invariant
that a burn is one file with one owner. WorkManager (not `DownloadManager`) because workers
must write app-private storage and survive process death.

### D6 — Persistence: JSON documents with iOS file + field names verbatim, one `VersionedJsonWriter`, DataStore for prefs, Keystore `SecretStore` for every secret, no Room
Every document (collections v7, activity, play-history, play-stats, playback-session v1,
mix-decks v1, mix-sessions v2, burns v1, transfers, studio v1, scoreboard, onboarding
marker, widget snapshot) keeps the iOS file name and CodingKeys so the S3 profile sync can
union them across platforms; all additive-optional, `PdjJson.lenient`, atomic temp+rename.
**COL-2** ships `data/store/VersionedJsonWriter.kt` (monotonic version, off-main,
`invalidate(through:)` seam) which MIX-1, PB-4 and STU-1 reuse. Non-secret prefs stay in
Preferences DataStore via `PrefKey<T>`. ALL secrets (rip token, jukebox token,
Music-User-Token, aoss search creds, diag key, profile secret) live in
`data/credentials/SecretStore.kt` (EncryptedSharedPreferences, one-shot migration that
blanks the DataStore copies) created in SURF-1; the audits' `SecretBox`,
`DiagCredentialStore` and `DiagKeyStore` are folded into it.

*Why:* three audits each invented a Keystore wrapper and two invented a versioned writer;
the sync engine needs one reload/invalidate seam per store, not per author.

### D7 — Profile sync without CloudKit: verbatim `CloudSyncService` port over `CloudDocDatabase`, backed by S3 through the first-party `pocketdj-profile-sync` Lambda
**SVC-7** ports the iOS whole-document LWW engine unchanged (2 s skew, `.pre-cloud` backup,
watermarks, merge-on-reload, meta-probed `pushDirty`, onboarding push gate, 8 s launch
deadline) against an in-memory database; **SVC-8** ships the Lambda (S3
`profiles/<profileId>/<key>.json`, HMAC profile secret, optional remote-endpoint key
`profileSyncBase` — absent ⇒ sync disabled); **SVC-9** adds `S3CloudDocDatabase`, enrollment
and link-a-device (QR/code), which also replaces onboarding stage 1's iCloud branch ("Use
on this device" / "Link a device"). Synced docs register through `FeatureModule.syncEntries`.
The iOS owner gate (iCloud `userRecordID` hash) is N/A: favorites two-way sync (**COL-11**)
and the owner seed are per-install opt-ins defaulting OFF.

*Why:* the engine is already pure over the database interface and unit-tested; only the
backend changes. Identical doc shapes mean iOS and Android profiles merge with no
migration. This resolves the living doc's open question #2.

### D8 — One diagnostics stack (`diag/` + `net/SigV4.kt`) in wave 2; channel gate = `BuildConfig.DEBUG || DIAG_CHANNEL`
PB-9, DIAG-1 and DBG-1 merge into **SVC-5**: `DiagLog` (ring buffer, 500-line parts, 40k
cap, 15 s/3 s flush, buffered-until-key), `NPLog` lanes with the iOS grammar so
`scripts/deadair-report.py` reads `android-<id8>` logs unchanged, hand-rolled SigV4 PUT
over OkHttp (shared `net/SigV4.kt`, also used by online search **BRW-5**), `.pdjdiagkey`
import, `JankWatchdog`, Settings ▸ Debug screen + upload status. Release builds never
upload.

### D9 — History outcomes are ONE package: PB-5
HIST-1 (browse), PB-5 (playback) and GAMES-6 (games) specified the same contract three
times. **PB-5** owns `playback/outcome/SkipTracker.kt`, the PlayEvent fields `wasSkipped`,
`listenedFraction`, `tzOffsetMin`, `originInstallId`, `originCollectionId` (iOS JSON keys;
`carPlay`/`listeningContext` reserved, never renamed), `PlayProgress`/`PlayAdvancedAway`/
`PlayStopped` events on `PlayEventBus`, `markSkipped`/`noteListened` max-merge, the
`PlaySource.GAME`/`PlayContext.game(runTag,label)` and `PlaySource.MIX` tokens, and the
`PlayOutcomeListener` registry. History UI (BRW-6), hide-skips (BRW-2), In the Pocket
(GM-7), listening pockets (COL-17), play-stats (SVC-6) and the Mix bridge (MIX-16) depend
on it. The rule (strict `< 0.5` skip, high-water position, one-deep previous stash) lives
in one place and the recording site stays single (the sequencer/service).

### D10 — Id collisions and duplicates resolved (every fold recorded in `source_ids`)
SYNC-1(collections)→COL-7 source-sync; SYNC-1(services)→SVC-7 cloud docs.
ONB-1(services)+ONB-1(surfaces)→SURF-3. LP-1(browse) folded into COL-16/17/18.

provider→PB-4). PB-9+DIAG-1+DBG-1→SVC-5. HIST-1+GAMES-6→PB-5. LYR-1→BRW-4. RA-1 absorbs
HIST-3's recently-added derivation→COL-12; HIST-3 keeps the collection timeline→BRW-7.

SET-1 reset→SVC-13 (with RESET-1). SRCH-1 SecretBox + diag credential stores→SecretStore
(SURF-1). GAMES-4's AddToCollectionSheet params→COL-4. GAMES-5 owns
`data/pockets/PocketsModels.kt`; COL-16 extends it. DMX-1's StemClient→SVC-11. EXPL-1 owns
`IndexSong.dateAdded`/streaming links; RA-1 consumes. The Apple Music Web API client

### D11 — Playback core first: sequencer owns the queue, ExoPlayer holds a 1–2 row window, zero-dead-air discipline before any surface
**PB-1** (SetlistSequencer, per-row resolve ladder, `RowResolverRegistry`, `playUrl` seam
for jukebox Tune-In, `appendRows(runTag)` for games) lands in wave 4, **PB-2** (session
transport + arbiter) wave 5, **PB-3** (runway/watchdogs/stall hop/cascade breaker/rip
window/live backstop/supervisor/DeadAirMeter) and **PB-6** (Now Playing deck + mini bar)
wave 6. Android never fires passive stream-through rips; rip-on-demand inside a run is
explicit per row, gated by the rip-ahead window (playing + next 10) with `/rip-cancel` on
eviction; interactive ▶ waits ≤20 s then returns `StillRipping` (**SVC-1**). Pause
discrimination comes from Media3 change reasons, never timing heuristics. The 30 s preview
rung never appears inside a sequencer run.

*Why:* the iOS dead-air program is the app's core guarantee and every surface (lock
screen, Auto, widgets, games, jukebox) drives the sequencer.

### D12 — Apple Music on Android: vendored MusicKit AARs for sign-in + DRM full-track (device-only), one REST client for everything else
**SVC-15** `data/applemusic/AppleMusicApi.kt` wraps the Apple Music REST API with the
developer token Android already mints plus the Music-User-Token from the vendored auth AAR:
catalog search (Discover, **BRW-15**), library playlists CRUD (write-back **COL-8**, playlist
sync **COL-9**), favorites (**COL-11**), artists/latest releases (**BRW-14**). Full-track
playback stays on the vendored mediaplayback AAR via `AppleMusicPlayerAdapter` (**PB-8**) and
is device-only; 30 s previews are the emulator path. rip-server and jukebox HTTP APIs are
unchanged. *Why:* four packages each specified a partial REST client; MusicKit-for-Android
has no search/library API worth vendoring; iOS itself does write-back over the Web API.

### D13 — Catalog stays CloudFront offline-first; compiled-in endpoints = green account; remote-endpoint config may add keys only
**SVC-12** pins `config/endpoints.green.json` by JVM test (the blue account was deleted
2026-10-15), keeps disk-cache-first + conditional refresh, and adds the optional
`profileSyncBase`/`diagBucket` keys read at request time so an account move never needs a
release.

### D14 — Verification doctrine per package
Every package carries `unit_tests` (JVM, iOS fixtures copied verbatim under
`src/test/resources`), `emulator_steps` (headless AVD `pocketdj`, API 36, `-no-audio`:
transport/state verified through diag heartbeat lines and `OfflineRenderer` probes) and a
`device_only` string. Acceptance for every package includes **"the JVM test COUNT increased
by the package's new tests"** (the XcodeGen zero-tests trap applies to Gradle too — exit 0
with zero tests has shipped broken builds before) and **"the `ARCHITECTURE-ANDROID.md`
status ledger row updated"**.

### D15 — Games placement and game-run playback
Games is the 7th destination registered through the nav registry (compact width: labels on
the selected item only); engines live in the `GamesGraph` sidecar; game runs append
ExoPlayer-only rows (manifest streams, 30 s previews for `appleMusicId` songs) to the
sequencer under a run tag and never the native AM full-track engine; MwF ships without push
(the 4 s poll is the source of truth on iOS too); In the Pocket runs time-only until
COL-19/20 ship the location engine.

## 3. Per-area architecture (condensed, reconciled)

Each subsection condenses the audit's `architecture` markdown and notes where a roadmap
decision overrides it. Package layouts are the audits' unless a decision moved a file.

### 3.1 Playback core + Now Playing (`audits/playback.json`; PB-1…PB-10)

**Where Android stands.** `PlaybackController` is a facade over ExoPlayer's playlist (▶
resolves one song → `MediaItem`s with `PlaybackContract` extras → `setMediaItems`);
`PlaybackService` (`MediaSessionService`, same process — never add `android:process`) is
the single History emitter. `QueuePlan` resolves a setlist at build time. `AppleMusicBackend`
is a second engine with no session. No sequencer, no Now Playing deck, no durable session,
no dead-air discipline, no diag upload.

**Core decision (D11).** `playback/sequencer/SetlistSequencer` (app-scoped, `@MainThread`
state, `StateFlow<SequencerState>`) is the Android `SetlistPlayer`: it owns
`queue: List<QueueItem(uid)>`, `index`, `isRunning`, `isHeldForResume`, source, captured
context/origin, repeat/shuffle (+`canonicalOrder`), `waitingForLive`, `pausedByCascade`,
`playbackNotice`, `playGeneration`. **ExoPlayer's playlist is not the queue**: the sequencer
loads the current row (and after PB-10 the next already-resolved local/rip row for gapless
boundaries); AUTO transitions / `STATE_ENDED` / errors come back as `handleEnded` /
`handleFailed`. `startPlayCurrent(fresh, resumeAtMs)` is the ONLY spawn funnel: cancel the
previous job, `if (!isActive) return`, claim `++playGeneration`, then the per-row ladder via
`RowResolverRegistry` — (1) local burned file (SVC-4 resolver; clip window), (2) manifest
rip stream, (3) Apple Music full-track when the song is AM-sourced or the rip is not instant
(iOS `ripStartsNow`), (4) rip-on-demand `pdj-resolve://song/<id>` resolved lazily by a
`ResolvingDataSource` inside the service while the row is already current, (5) none →
`advanceToNext(UNPLAYABLE_HERE)`. After every `await`, guard `isActive && gen == playGeneration`.

**Session transport (D2, PB-2).** `SequencerForwardingPlayer(exoPlayer)` is what the
session shows: next/prev/repeat/shuffle forward to the sequencer, `play()` on IDLE runs the
`onIdlePlay` ladder (`resumeHeld` / `startCurrent` / `startInFlight` ignore) or latches
`pendingRemotePlayAt` (15 s); set-gated command availability; `play()` on BUFFERING is a
re-kick, never a pause; ♥ is a `CommandButton` (`pdj.favorite`) behind `FavoriteSeam`.
`SessionSwitchboard` swaps `mediaSession.player` between the forwarding player,
`AppleMusicPlayerAdapter : SimpleBasePlayer` (PB-8; `endReason` verdicts SYSTEM_SKIP /
NEVER_STARTED from SDK callbacks + 400 ms poll) and `MixSessionPlayer` (MIX-11) so there is
exactly one card. `announceUpcoming` = load the new row's `MediaItem` with full metadata and
artwork immediately, even if its URI is `pdj-resolve://`.

**Zero dead air (PB-3).** `PlaybackRunway` = partial WakeLock (25 s cap) from
`startPlayCurrent` to first audio; first audio = `onIsPlayingChanged(true)` with READY (or
AM PLAYING) → `DeadAirMeter.firstAudio()`; start watchdog 8 s re-kick / 20 s escalate;
resolve-stall hop at 6 s moves the first on-device (else instant-start) row within 50 ahead
to `index` and defers the stalled row behind it; pause discrimination from Media3 reasons
(`USER_REQUEST`/`REMOTE`/`AUDIO_BECOMING_NOISY` = listener pause; transient focus loss =
interruption open); cascade breaker, rip window (playing + next 10, `/rip-cancel` on
eviction) and live backstop (length + 45 s) are pure ports; `PlaybackSupervisor.Core.step`
verbatim (L1 3 s / L2 +12 s ≤2 per song / L3 +8 s); `DeadAirMeter` writes
`filesDir/pocketdj-dead-air.json` and emits the **character-identical** `[deadair]` lines so
`scripts/deadair-report.py` works on `android-<id8>` logs. Backend names `burned`, `rip`,
`hls`, `appleMusic`, `none`.

**Durable session (PB-4).** `pocketdj-playback-session.json` with the iOS `Snapshot` shape
(schemaVersion 1, `pses_<uuid>`, song-relative `positionMs`, `repeatMode "off|all|one"`,
opaque `stemLock`), written through the shared `VersionedJsonWriter` on play / every index
move / every live edit / pause-resume immediately / 1 Hz throttled to 5 s. `restoreIfIdle()`
at graph init rebuilds the queue HELD (no audio, no card, no write); first ▶ →
`resumeFromHold()`; `ON_STOP` flushes snapshot + DeadAirMeter + SkipTracker checkpoint.
Also provides the Media3 playback-resumption provider (held queue, never auto-play).

**History outcomes (D9, PB-5)** — see §2. **Now Playing UI (PB-6/PB-7).** Route
`nowplaying` pushed by the mini bar and every ▶/🔀 funnel; `RecordPlayer` Canvas platter
spins at `clamp(bpm/4, 8, 120)/60` rev/s (33⅓ RPM fallback), frozen in place on pause, only
while the audible track is the deck's row; transport through `NowPlayingTransport.togglePlayPause`
(held → resume; cascade → startCurrent; AM → AM toggle; idle+start pending → ignore);
notice banner; Up Next windowed 200 with uid-safe reorder/remove/menu; Played list with
Rewind-to-here; add-search (200 ms debounce, off-main); "Open set list" →
`materializeNowPlayingSetlist`; landscape/tablet flanks. Mini bar hidden while a Mix session
owns audio. PB-6 also defines `NowPlayingDspSeam` and `mixSessionActive` so MIX-18 plugs in
without touching the sequencer. Jukebox inserts route through the sequencer (PB-7).

**Verification.** JVM: `FakePlayerPort` over the MediaController calls, `runTest` virtual
time for watchdogs/hops/backstops, table-driven Supervisor/CascadeBreaker/RipWindow/
DeadAirMeter/SkipTracker/endReason, iOS fixture round-trips. Emulator: real public rip
URLs, `dumpsys media_session`, `cmd media_session dispatch`, `am kill` + relaunch for held
restore, airplane-mode for stall/hop/cascade. Device-only: AM full-track rows, AM card,
Bluetooth route loss, Android Auto.

### 3.2 Mix (`audits/mix.json`; MIX-0…MIX-18)

**Engine (D1).** In-process, pull-based float graph in Kotlin rendered by one `AudioTrack`,
MediaCodec mp3 → PCM per voice on worker threads, Media3 `SonicAudioProcessor` for per-deck
tempo/pitch. Not ExoPlayer-per-voice (four players started by host time land samples apart
and comb-filter — the iOS `StemSync.startTogether` lesson; the 60 ms main↔stems handover,
pre-fader cue split, house sum, house pan and master limiter are all inexpressible across
independent players), not C++ today (no NDK in the SDK, zero C++ in the repo, implementers
verified by JVM tests; a pure-Kotlin graph renders offline into a `FloatArray` so ">2 ms of
silence across a rapid stem toggle fails" is an ordinary unit test). Latency budget is a
deck's (~30–60 ms control→audio is inaudible); 3-period buffer rides out ART GC pauses; the
render loop allocates nothing. **Accepted cost:** Sonic is a notch below
`AVAudioUnitTimePitch` beyond ±25 %; Auto-DJ glide ≤10 % and Sync ≈ ±15 % are clean. A
Rubber Band/SoundTouch JNI `TimePitch` can replace the Sonic wrapper behind the same
interface if ever needed.

**Reconciled with D1/D2/D5/D6:** the audit's `mix/audio/` and `mix/dsp/` become the shared
`audio/` (MIX-2) and `audio/dsp/` (MIX-3) packages; the audit's `MixService`
(MediaSessionService) is **replaced** by `MixSessionPlayer : SimpleBasePlayer` handed to the
one session via `SessionSwitchboard` (MIX-11); the audit's `AudioOwnerArbiter` is PB-2's
switchboard; `data/burns` + `TransferCoordinator` are SVC-2/SVC-3; `VersionedJsonWriter` is
COL-2's.

**Graph topology** (same as `docs/design/mix-audio-graph.md`): per deck `mainVoice` + 4 stem
voices → `inputSum` (envelope tap) → `TimePitch` → slot0…slot3 (each comp→filter→reverb→mod,
≤1 un-bypassed, bypass-flipped never rewired) → `Eq3` (320 Hz shelf / 1 kHz peak / 3.2 kHz
shelf, ±12 dB) → `Trim` → `mainGain` (min(vol,1)·xfade) and `cueGain`
(cued ? cueVol/max(vol,1) : 0, panned to the cue side); `houseSum` → **recording tap** →
`housePan` (±1 only while any deck is cued) → `mainSum` (+ cue sends) → `Limiter` →
`AudioSink`. Everything after `inputSum` runs at the sink rate, stereo float, block = sink
period. The render thread pulls each `Voice.read()` from its SPSC `FloatRing` (empty + not
complete = STREAM HOLD), applies gains, chains DSP, taps, writes; exposes `renderFrame` =
the shared render clock for scheduled starts, handover fades and loop wraps. Decoder
threads walk mp3 frames ≤ `frontierBytes` (`Mp3FrameReader`: Xing/Info/VBRI, LAME encoder
delay, 576 priming rule for untagged stems, 529 decoder delay). `VoiceGroup.startTogether`
computes ONE render frame for all stems; `Handover.schedule` ramps linear gains inside the
render loop (frame-exact). Loops wrap the read position inside `[loopStart, loopEnd)` on the
render thread. Parameters travel as an immutable `RenderParams` swapped via
`AtomicReference`; gains ramp over one block; `delayTime` is set only from the BASE strength.

**Engine (main thread).** `MixEngine` is `@MainThread`, app-scoped, never torn down on
leaving the tab; `StateFlow<MixUiState>` for cold state, polled holders for hot values
(`DeckPositions` at 10 Hz, `MixDeckLevels` VU, `truePlayhead` for the 60 fps beat pulse).
10 Hz tick (dt ≤ 0.5 s): stream hold → freeze playhead + push auto end clock; loop fold;
advance; frontier catch; end → retire; watchdog branch; `AutoDj.fire()`; persist positions;
session position ~1 Hz. Sub-controllers (`DeckController`, `LoopController`,
`StemController`, `AutoDj`, `GlideMachine`, `StreamDecks`, `MixPersistence`,
`MixRecordingHooks`) share an internal `EngineCore` and live in separate files so packages
stay disjoint. Audio focus GAIN on start; transient loss → `remotePause()` with
`interruptionParked`; routing change → `recoverFromSinkStop()` (recreate the track at the
new rate, re-prime voices, park/unpark clocks).

**Data flow.** Crate pick → `MixResolver` (collections, catalog, burns, canStream) →
`[MixLoadable]` → `AutoDj.startAutoMix` / `CollectionMixDownloader.begin` (onDisk |
burnQueue | needsRip; serial burn lane; rip poll 4.5 s; 30 s throughput window; 256 kbps
ETA) / `engine.load` (cut preferred, analog `startMs`+`lengthMs` window, else
`MixStreamLoader.open`). Deck controls → setters → state + `RenderParams` swap + `rec(event)`
+ persist. `MixPlayOutcomeBridge` → History (MIX-16); `onAirTrack`/`autoUpcoming`/
`autoQueueInsert` ↔ Jukebox when a mix is live.

**Persistence (D6).** `pocketdj-mix-decks.json` schemaVersion 1 (flat FX fields beside
optional `fxSlots`; `isEmpty`/`isExhausted` reject), `pocketdj-mix-sessions.json`
schemaVersion 2 (`MixEventKind` with `unknown(raw)` round-trip), burns through SVC-2,
`cacheDir/mixstream/` swept at launch, `filesDir/mix-sessions/<id>/recording-N.aac` (ADTS,
append-only, crash-safe). Settings keys `mixAutoLeadSeconds`(15), `mixAutoFadeSeconds`(3),
`mixSkipFadeSeconds`(15), `mixGlideSeconds`(10), `mixAutoHidePlayed`(true),
`mixCueChannel`("right"), `mixBeatPulse`(false), `mixDeckLayout`("stacked") in the Mix's
own `MixSettings.kt`.

**Invariants reviewers check** (the audit's §6, verbatim intent): stems start on one frame
(r > 0.999 vs full mix); one handover fade at a time, intent moves, landing re-runs the
decision, >2 ms silence fails; stem ON is transactional; Auto-DJ never sweeps onto a silent
deck, held seconds don't burn the end clock; skip ignored mid-fade except a fade frozen on a
buffering incoming deck; lock-screen ⏸ SUSPENDS the Auto-DJ, in-app master pause ENDS it;
restore is parked at launch and materialized held on the Mix tab; auto sweeps aren't user
`.crossfader` events; gain-split identity, `applyBoost` never on the crossfader path;
streaming failure before audio ejects + skips 0.5 s if live, cooldowns 120 s/60 s, max 3
streams, pinned never cancelled; progressive eligibility touches only OUR mix; the crate
menu never recomposes while open; position ticks never recompose the screen.

**Emulator vs device.** `-no-audio` still accepts `AudioTrack` writes, so transport, state,
handover and Auto-DJ logic are verifiable via `MixDiag` heartbeats (`render=1 tapAge≈0`) and
`OfflineRenderer` probes; audible output, cue routing on a real interface, Bluetooth, phone
calls and lock-screen controls are device-only.

### 3.3 Producer / Studio (`audits/studio.json`; STU-1…STU-16)

**Engine (D1, Studio half).** One NDK module `cpp/pdjdsp` (CMake, C++17), thin JNI; **all
scheduling, state, persistence and musical math in Kotlin.** Why native here: the iOS
arranger was forced off per-node graphs onto ONE render callback (`MultitrackPlayer`), and
the Android analogue is an Oboe data callback — Java `AudioTrack.write` loops add 20–40 ms
jitter and cannot host a SoundFont synth with playable latency; there is no platform SF2
synth (TinySoundFont, MIT, one preset per staff); tempo/pitch (0.5–10×, ±12, span stretch,
strip bake, Beat Match) uses Signalsmith Stretch OFFLINE only. The C++ surface is small:
PCM mixer, TSF wrapper, stretch wrapper, float-array ports of TrackFX/MasterFX kernels
(also callable offline so bounce ≡ live). Reconciled with D1: the audit's `StudioOutput`
becomes `OboeSink : AudioSink` (STU-2) over MIX-2's `RenderGraph`/`Voice`/decoders;
`AudioTrackSink` is the emulator default. Pure-Kotlin DSP kernels mirror the C++ copies and
a golden test cross-checks them.

**Codecs.** `MediaExtractor`+`MediaCodec` → canonical 44.1 kHz stereo Float32 on import;
AAC `.m4a` via `MediaCodec`+`MediaMuxer`; loops are **LPCM `.wav`** with an authoritative
frame count (documented divergence from iOS `.caf`); DRM imports rejected when
`getDrmInitData() != null` or decode fails.

**Packages.** `studio.model` (serializable mirrors with iOS keys; `StudioSource` custom
discriminator), `studio.store` (`pocketdj-studio.json` over `VersionedJsonWriter`,
`StudioFolders` SAF roots, `StudioReconcile` — never prune on an unreachable root),
`studio.audio` (`StudioRender` offline: renderSample/renderLoop/bouncePattern/carve*/
stretch/mixPCM with FX-tail drain to −60 dBFS or 3 s; `LocalAudioCache` façade over
BurnStore per D5), `studio.dsp`, `studio.engine` (`StudioEngine` pattern scheduler with
`StudioPatternClock`, rolling `armSlot` horizon, mono-choke; `InstrumentEngine` with the
lock-free `InstrumentEventLog`; `MicRecorder`; `MultitrackPlayer`; `ArrangerBouncer`,
`ArrangerClipBaker`, `ArrangerBeatMatch`; `AudioFocusPolicy` — mic-capture-active flag every
play path consults), `studio.midi` (USB + BLE via `MidiManager`, SMF read/write),
`studio.score` (quantizer, layout, playhead, `PdfDocument`), `studio.packs` (offline-first
index, streamed download + sha256 + atomic install), `studio.demux` (`DemuxStore`
`demux-cache/<key>.json`, chord/drum/melody/key detectors, stems via SVC-11),
`screens.producer` (7 sub-tabs, `studioTab` persisted, icon-only on compact).

**Threading rule (load-bearing).** MIDI receive calls `nativeNoteOn` directly and appends
to the event log under an `AtomicReference` ring; UI highlights drain at 30 Hz, staff
publishes ~10 Hz, never per-note main-thread posts. Offline renders on `Dispatchers.Default`
inside a single-permit `Mutex`. Starting a Studio engine goes through the D2 switchboard
(pauses the sequencer, requests focus); `onErrorAfterClose`/device callback → rebuild stream
and re-prime (the zombie-node lesson). Tiers: T0 models/store/shell/Samples/Loops/Sequencer/
Cues/collections playback (STU-1…7), T1 Instruments/MIDI/Arp/Tracks/Demux core
(STU-8…14), T2 Demux extras + hardening (STU-15/16).

## 7. How implementers work

**The spec for a package = its `roadmap.json` entry + its area audit + this document.**
Read them in that order. The roadmap entry carries `title`, `goal`, `files` (the files you
own), `shared_touchpoints` (files you may edit additively), `depends_on`, `acceptance`,
`unit_tests`, `emulator_steps`, `device_only`, `est_lines`, `priority` and `source_ids`
(which audit package(s) it was built from — read those in the audit's `packages` array for
the long-form spec). The audit's `inventory` rows for your feature point at the exact iOS
file:line ranges to port; the audit's `architecture` gives the area's package layout and
invariants; **where the audit contradicts §2 of this document, §2 wins** (the common cases
are listed per area in §3 under "Reconciled").

**Mechanics** (automated by `android/specs/parity/wave-workflow.js`, phases Implement →
Review → Fix → Integrate):
1. One worktree + branch per package: `parity/<ID>` under
   `/Users/deepspacenine/forges/levi/pocketdj-parity/<ID>`, branched from
   `feat/android-parity`. Progress lives in git (WIP commits after every sub-step that
   compiles) and in `android/specs/parity/status/<ID>.md` (`state: in-progress | merged`,
   a sub-step checklist, deviations, any file touched outside the owned set). A run killed
   by a session limit is re-launched and resumes from what is committed.
2. Stay inside `files` + `shared_touchpoints`; the other packages in the wave run in
   parallel on disjoint files. After wave 1, never edit a hot file (§2 D4) — register through
   your area's `FeatureModule` sidecar and declare settings keys in your own `*Settings.kt`.
3. Port BEHAVIOR from `apple/PocketDJ` faithfully, including every hard-won invariant the
   audit names; keep iOS file names and JSON keys verbatim (D6); add fields
   additive-optional; decode leniently; write atomically.
4. Tests: real JVM unit tests for pure functions, state machines, serialization and
   iOS-shape JSON compatibility (fixtures copied verbatim from iOS under
   `src/test/resources`). Build with
   `./gradlew :app:testDebugUnitTest :app:assembleDebug` (JDK 21, `ANDROID_HOME` set) and
   **confirm the test COUNT in `app/build/test-results/testDebugUnitTest/*.xml` moved** —
   a test file Gradle did not pick up still exits 0 (D14). Implementers do not touch the
   emulator; the wave integrator owns it.
5. Review: an adversarial review of the diff (MAJOR/MINOR/NIT with failure scenarios);
   MAJOR and MINOR findings are fixed before integration.
6. Integrate: the integrator merges each `parity/<ID>` with `--no-ff` into
   `feat/android-parity`, resolves hot-file conflicts preserving both sides, runs the full
   JVM suite, installs on the headless `pocketdj` AVD and runs each package's
   `emulator_steps` (device-only steps are recorded as not verifiable), marks status files
   `state: merged`, appends a wave section to `android/specs/parity/PROGRESS.md`, pushes.
7. Every package's acceptance ends with the same two lines: the test count increased, and
   the `ARCHITECTURE-ANDROID.md` status ledger row for the package is updated
   (DONE/PARTIAL + what is device-only). The living doc stays honest about what is built.

**Changing the plan.** Edit `android/specs/parity/tools/spec_*.py`, re-run
`build_roadmap.py` and `check_roadmap.py` (dependency order, disjoint files, one owner per
hot file per wave), then update §2/§3 here if a decision moved. Never hand-edit
`roadmap.json`.
